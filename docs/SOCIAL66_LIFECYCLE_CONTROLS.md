# SOCIAL-66 — базовые действия, служебные группы и геймпад

17 октября 2026. Исправление по владельцу после SOCIAL-65 реализовано и
установлено на Odin/Flip. Проверки исходников, устройств и оставшаяся приёмка
разделены ниже; прежняя поставка не подменяет новые результаты.

## Принятый результат

- Удаление друга и выход из группы — базовые действия. Они доступны из Select /
  многоточия с подтверждением; история лички после удаления друга сохраняется.
- Группа, созданная лобби, является его служебным разговором. Она не входит в
  Social, его восстановленный разговор и обычные уведомления о группах.
- Закрытие лобби удаляет участников через Fluxer и затем хозяина. Офлайн-участнику
  не требуется открыть TrainerOS для завершения этого удаления. Выход хозяина с
  передачей управления другому игроку сохраняет разговор действующего лобби.
- Крестовина/стик, A/B и Select позволяют дойти до заголовка, сообщений и всех
  кнопок ввода; фокус виден. R3 сразу открывает клавиатуру, L3 — сведения.

## Идентичность разговора

Не использовать название, список друзей или текущую открытую вкладку как
эвристику. Новая служебная группа создаётся без гостей; перед их добавлением
записывается и закрепляется версионированная метка с UUID лобби, ID группы и
ID автора. Обычный чат и одинаковое название не становятся служебными.
У получателя неизвестная группа допускается в Social после проверки метки;
сбой запроса не превращает неизвестное в обычную группу. Проверки повторяются.
Привязки сохраняются по локальному профилю и Fluxer-аккаунту, независимо от
текущего списка комнат; переименование/передача хозяина их не стирает.

Метка используется для классификации, а не как удалённая команда удаления.
Удаление требует принятой локальной комнаты с теми же ID; перед каждой фазой
проверяются реальный тип группы, доступ и хозяин Fluxer. Очередь очистки
записывается до первого запроса, повторяется после сбоя/перезапуска. Нельзя
удалять обычные группы по одному лишь похожему названию или чужому сообщению.

Старые группы без метки и без сохранившейся привязки нельзя надёжно отличить
от обычных. Их нельзя автоматически массово удалить по догадке. Активные
старые привязки учитываются отдельно; миграция должна сохранить чужие обычные
разговоры, которые ранние версии позволяли использовать в лобби.

## Выполненные проверки

- [x] Автоматизированный транспорт: пустая группа → сообщение-метка → pin →
  добавление гостя. При неудаче закрепления участники не добавляются.
- [x] Одинаковые названия, переименование, восстановление реестра, обнаружение
  метки без местного реестра, неверный ID/автор метки; скрытие неизвестной группы.
- [x] Удаление получателей раньше хозяина, частичный HTTP-сбой и повтор,
  защита обычной группы. Новый хозяин сначала проверяет метку, даже если принял
  комнату раньше фонового запроса; сбой оставляет очистку в очереди.
- [x] Контроллер: пустая личка, заголовок/сообщения/строка ввода, R3, B,
  подтверждение удаления друга; регрессии истории и одиночного вложения.

в разговоре лобби; внешнее удаление/вытеснение метки не проверено. Не считать
это доказательством произвольных изменений группы сторонним клиентом.
