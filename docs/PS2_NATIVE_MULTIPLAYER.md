# PS2: LAN и серверный Online

**Решение владельца, 24 октября 2026:** после завершения текущей работы над PSP
заняться PS2 по двум предоставленным спискам. Этот проход сохраняет и изучает
каталог. Реализация, установка и игровые проверки PS2 сейчас не начинаются.
Связанные требования: [R035](FEATURE_READINESS.md#r035), [#259](https://github.com/EriArk/TrainerOS/issues/259), [#187](https://github.com/EriArk/TrainerOS/issues/187).

## Уточнение из нового issue #259 — сверка 24 октября

**Последнее уточнение владельца в чате:** текущая работа — изучение самой
реализации ARMSX2 и установленной сборки **в сравнении с альтернативами**. ARMSX2
не предопределяет выбор транспорта. Не начинать писать адаптеры или сетевой агент
по одному описанию задачи. Сначала представить фактический механизм, пригодные
существующие части и конкретные пробелы.

[#259](https://github.com/EriArk/TrainerOS/issues/259), созданный 24.10, задаёт
первый PS2-блок: **нативный Ethernet LAN через интернет**, установленный ARMSX2
DEV9 и небольшой агент на каждой портативке только на время сессии. Общий
аутентифицированный транспорт остаётся владельцем [#106](https://github.com/EriArk/TrainerOS/issues/106),
а не второй сетевой реализацией внутри PS2. Его возможности позднее может
использовать PC LAN #251. Это уточнение цели, не новая реализованная функция.

До реализации проверить реальные выходные пакеты установленного Local Link:
L2/IP/собственный UDP-формат, выбор endpoint, broadcast/multicast и discovery.
Начать с одного точного LAN-издания, записать минимальное техническое решение
и использовать userspace, если фактический интерфейс это позволяет. TUN/TAP
требует доказанной необходимости. Не соединять домашние LAN, произвольные порты,
DNS и маршруты; агент обслуживает только принятую игровую сессию и её участников.

Предпочтение — настоящий локальный путь либо прямой P2P; резервное реле допустимо
только при наличии реально доступного авторизованного сервиса. `libjuice` и Pion
TURN в issue — кандидаты для оценки, не предписанная замена существующего
транспорта и не поручение разворачивать VPS. Реле на портативке само по себе
не решает недоступность через CGNAT. Недоступный fallback показывать честно.

Один GameHub Lobby, автоматическая подготовка, Ready и действующий явный Start
хозяина; вход/создание матча — в LAN-меню игры. Offline Local не требует Fluxer.
Обычный вход не требует IP, VPN или выбора сетевого протокола. Нативный серверный
Online остаётся отдельной работой по проверенным профилям игр/сервисов; LAN-туннель
не восстанавливает закрытые игровые серверы. LRPS2 остаётся остановленным.
Все условия #259 сохранены в issue; таблица игр фиксирует фактические результаты.

### Механизм Local Link

- DEV9 передаёт Ethernet-кадры до 1514 байт через собственный IPv4 UDP-протокол
  `ECLX`, версия 1. Заголовок — 44 байта, полезная часть фрагмента — до 1000 байт,
  до двух фрагментов на кадр. Это не обычный UDP-порт самой PS2-игры.
- Хост слушает выбранный порт (по умолчанию 19072), клиенты знают его адрес/порт.
  Топология — звезда: хост пересылает кадры остальным зарегистрированным участникам.
  Фильтр принимает собственный MAC, broadcast и multicast; DHCP перехватывается
  внутри DEV9, MAC/IP различаются по peer ID. Перенос этих классов кадров подтверждён
  кодом; обнаружение соперника конкретной игрой ещё не установлено.
- Есть HELLO раз в секунду, nonce сессии, окно последовательностей и ограниченная
  сборка фрагментов; устаревшие сборки удаляются через 2 секунды, peers — через 10.
  Нет повторной доставки игровых кадров, ICE/STUN/TURN, автоматического поиска
  хоста или согласования портов. Потерянный фрагмент означает потерянный кадр.
- Room code задаёт ключ проверки SipHash, но содержимое кадра не шифруется.
  Общий room code не является персональным допуском Lobby. Привязка к принятому
  составу/поколению сессии и отзыв доступа остаются задачей общего транспорта.
  Сам Local Link bind использует все IPv4-интерфейсы, не только loopback.
- [Настройки установленной ревизии](https://github.com/ARMSX2/ARMSX2/blob/65fd14b9160e7fa3779794fc45c4e92a86772621/pcsx2-qt/Settings/DEV9LocalLinkWidget.cpp)
  уже имеют Host, адрес, порт, room code и peer ID. Смена endpoint/identity требует
  пересоздания DEV9, а не изменения одного поля во время активного соединения.

### Сравнение путей

| Вариант | Что уже есть | Что ещё выяснить перед выбором |
| --- | --- | --- |
| Local Link + существующий транспорт TrainerOS | Установленный userspace-выход Ethernet через UDP; не требует PCAP/TAP | Граница локального endpoint, безопасный допуск, MTU/потери/очереди и фактический datagram-контракт общего транспорта. Сам Local Link не решает NAT |
| DEV9 PCAP + XLink Kai | Готовый PS2 LAN-over-Internet сервис, Linux ARM64/aarch64 пакеты | Автоматизация аккаунта/arena через Lobby, права capture, совместимость Armada и сетевого интерфейса, NAT и лицензия поставки; наличие пакета не подтверждает этот путь на Odin/Flip |
| DEV9 PCAP + готовая виртуальная Ethernet-сеть, например ZeroTier | L2, broadcast/multicast и NAT traversal уже реализованы отдельным проектом | Автоматический краткоживущий admission/revoke, изоляция только игры, привилегии и обслуживание дополнительной сети. Не соединять домашние LAN; не требовать от игрока network ID/админки |
| Независимый PCSX2 Userspace LAN | Raw Ethernet через Unix datagram socket и локальный switch без root/TAP | Эксперимент для Linux x86-64; нет готового интернет-транспорта или подтверждённой ARM64-поставки. Полезен для сравнения минимальной границы DEV9, не готовая замена установленного runtime |
| Обычный DEV9 Sockets + существующий revival | Встроенные IP/TCP/UDP-сессии, подходящий путь к игровому серверу | Точное PS2-издание, сервис и его настройки. Sockets не создаёт общий Ethernet-сегмент между удалёнными игроками; серверный Online не подменять LAN |

Опоры сравнения:

- PCSX2 revision `5675313c6db3390fdc38f75a658ddfc68498103e`:
  [PCAP](https://github.com/PCSX2/pcsx2/blob/5675313c6db3390fdc38f75a658ddfc68498103e/pcsx2/DEV9/pcap_io.cpp),
  [Sockets](https://github.com/PCSX2/pcsx2/blob/5675313c6db3390fdc38f75a658ddfc68498103e/pcsx2/DEV9/sockets.cpp).
  PCAP передаёт L2 через выбранный интерфейс; в switched-пути остаётся TODO про
  loopback broadcast к хосту. Sockets содержит отдельную обработку UDP
  broadcast/multicast: утверждать, что он вообще их не поддерживает, неверно.
- XLink: [официальные Linux/ARM64 пакеты](https://www.teamxlink.co.uk/downloads.php),
  [настройка PCSX2](https://teamxlink.co.uk/wiki/PCSX2_XLink_Kai_Setup),
  [Linux/account/arena/права](https://teamxlink.co.uk/wiki/Installing_XLink_Kai_on_Linux).
  Прямой запрос wiki 24.10 вернул maintenance; содержимое руководств доступно в
  поисковом индексе, поэтому актуальный API автоматизации этим чтением не подтверждён.
- ZeroTier: [официальный протокол](https://docs.zerotier.com/protocol/) описывает
  зашифрованную виртуальную Ethernet-сеть, контроллер допуска и резервную пересылку;
  производительность резервного пути требует отдельной оценки.
- [Userspace LAN, revision 631e721](https://github.com/khant735/PCSX2-Userspace-LAN/blob/631e7211c68068ebafa43b4c963dd0efe09d378a/pcsx2/DEV9/userspace_lan.h):
  изучен сам backend, а не только README. Он использует `AF_UNIX/SOCK_DGRAM`,
  имеет A/B MAC и подробное журналирование. Автор сообщает об обмене диагностического
  homebrew; коммерческие LAN-игры не подтверждены. Не переносить эти ограничения
  или весь fork автоматически в TrainerOS.
- Серверный Online: [PS Rewired](https://psrewired.com/) и
  [инструкция obsrv](https://obsrv.org/wiki/index.php?n=Network.PCSX2) — отдельные
  сервисы с собственными изданиями/настройками. Личные карты памяти не заменять
  готовой чужой картой из инструкции.

**Вывод исследования:** фиксированной зависимости от Local Link нет. Сравнивать
два уровня отдельно: доступ к Ethernet внутри эмулятора и доставка между устройствами.
Общий [SDK preview](../sdk/NETWORK.md) пока обещает reliable-ordered records;
это не основание объявлять готовым произвольный realtime datagram-мост PS2.
Следующий исследовательский результат — проверенный способ автоматизации XLink
и точный контракт общего транспорта для одного выбранного LAN-издания, затем
сравнение объёма необходимых изменений. До этого выбор и реализация адаптера/агента
не начинаются. Никакие программы из таблицы сейчас не установлены этим проходом.

## Основа интеграции

Текущий PS2 runtime — обычный ARMSX2. [LRPS2 shared-console эксперимент](emulators/lrps2.md)
остаётся остановленным; подготовленные RetroArch bindings не являются PS2 LAN.
По [исходнику ARMSX2](https://github.com/ARMSX2/ARMSX2/blob/9d989ca933a85bb2f1d111fd3b9e5742ac7d2fbe/pcsx2/DEV9/LocalLinkAdapter.cpp)
в выбранной ревизии есть Local Link: пересылка Ethernet-кадров через UDP,
host/client endpoint, room code и отдельные MAC/DHCP-адреса участников. Это
кандидат для повторного использования. Наличие кода не доказывает его включение
в установленную Linux-сборку, автоматический проход NAT или игровой результат.

Владельцы прежние: S03 — runtime, запуск и карты памяти; S07 — соединение;
S06 — Lobby, допуск и явный Start; S08 — защищённые сохранения. Применяются
[F04](STRUCTURE_MAP_RU.md#f04) и [F12](STRUCTURE_MAP_RU.md#f12).
Разделить два маршрута: **нативный LAN через транспорт** и **нативный Online через
поддержанный игровой сервис**. Couch/Remote Play остаются отдельными режимами.

## Точка продолжения после PSP

1. Проверить сборку и конфигурацию ARMSX2 DEV9 на целевых устройствах. Сравнить
   имеющиеся Local Link, PCAP/XLink и существующий транспорт TrainerOS. Выбирать
   готовый работающий путь; не создавать новую синхронизацию PS2 или отдельный
   сетевой стек для каждой игры.
2. Довести общий LAN-цикл: Lobby → выбор совместимого издания → автоматическая
   подготовка сети → Ready → явный Start хозяина → меню LAN самой игры → возврат
   в ту же комнату. Кандидаты для начала — Star Wars Battlefront II и Gran Turismo 4;
   точные доступные издания и требования определяются перед реализацией.
3. Через тот же запуск подключить поддержанный Online revival. SOCOM II полезен
   как кандидат с двумя разными режимами. Настройку DNS, DNAS и аккаунта брать
   из фактического контракта сервиса; LAN-туннель сам по себе backend не заменяет.
4. Расширять общие профили на список, записывая режим, disc serial/регион/ревизию,
   runtime, зависимость от сервиса, лимит игроков, вход/выход и восстановление.
   Сохранять собственные карты памяти участников. Возврат сети/вход в чат не
   запускают игру; перезапуск и повторное подключение определяются возможностями
   режима и явным действием игрока.
