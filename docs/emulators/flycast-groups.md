# Flycast: групповой native multiplayer — 26 октября 2026

Убрана привязка native запуска к одному гостю. Dreamcast Online/DCNet запускает
до четырёх независимых клиентов; каждый выбирает комнату средствами игры и хранит
свои VMU. Размер группы не означает, что каждый игровой режим допускает четверых.
В карточке режима прямо указано «Group launch». GGPO остаётся отдельным парным режимом.

Naomi native cabinet link теперь имеет 2–4 места. Используются существующие
LobbyConnection/ICE/DTLS/SCTP: хозяин держит отдельное соединение с каждым гостем,
без нового внешнего сервера. Nearby не использует STUN; Online использует прежний
signaling и публичный STUN. Ограничения прямого соединения через сложный NAT сохраняются.
Maximum Speed использует serial link и остаётся двухместным; отсутствие поддержки
native link по-прежнему определяется эмулятором, а не именем ROM или списком тестовых игр.

## Владельцы и запуск

S06 сохраняет явные Ready/Start и собственное место каждого участника. S03 проверяет
точные игру/runtime/settings и совпадение пришедшего ready с назначенным местом P2/P3/P4.
Каждый кабинет имеет один локальный pad на порту A. Число кабинетов не создаёт новые
порты контроллера внутри эмулятора и не заменяет игровой multiplayer режим.

S07 переиспользует по одному LobbyConnection на гостя. До запуска хозяина должны
быть готовы все соединения. Локальный приватный JSON v2 содержит состав, собственное
место и Unix sockets; данные удаляются при отмене. Каждый native процесс остаётся в
собственном network namespace. Адреса кабинетов одинаковы во всех namespaces:
127.0.0.1:37391–37394. Endpoint резервирует порты остальных мест, сохраняет source
port и передаёт неизменённый native payload. Два байта source/target seat добавляются
только снаружи native пакета. Хозяин проверяет source по аутентифицированному каналу
и пересылает guest→guest; произвольных IP/портов в транспортном контракте нет.

Native ring/SyncReply/start остаются в
[закреплённом NaomiNetwork upstream](https://github.com/blueminder/flycast-dojo/blob/d0e47e572b1e7b355e88bda8308c89d0c5156cbf/core/network/naomi_network.cpp).
TrainerCabinetPlayers задаёт ожидаемое число: вместо прежнего раннего старта после
одного гостя patch ждёт весь состав; timeout не запускает частичный матч.
Защищённая очередь ограничена 1 MiB, native payload — 0x4004, транспортный record —
0x4006. Чужой source port, слишком большой пакет или подмена seat не дают доступа
к другому endpoint. Разрыв прекращает forwarding, но не завершает игровой процесс.
Нет автоматического повторного запуска; выход идёт через общий Home/save lifecycle.

Для cabinet добавлен session marker, необходимый существующему owned-window Home/exit.
Private пути Flycast теперь ограничиваются внутри native runtime; XDG_DATA_DIRS
системы сохраняется для Vulkan ICD. Обычные Flycast и личные настройки не меняются.
Пакет меняет settings на `flycast-cabinet-private-v2`; старые парные пакеты не
смешиваются с новым wire format. Состав должен занимать последовательные места от P1.

## Проверка и поставка

Проверки используют реальные отдельные transport/endpoint процессы и namespace,
а native UDP child — протокольную fixture. Это проверка маршрутизации и lifecycle,
не доказательство игрового матча. Проверяются 2/3/4 кабинета, все направления,
advertised native port, максимальный пакет, отказ чужому source/oversize и сохранение
child при disconnect. Дополнительно — несколько LobbyConnection, уникальные
connection IDs, отдельное удаление гостя, GameParty dispatch P2/P3/P4 и отказ чужому ready.

Проверки: 4/4 shell suites, 2/2 transport suites, все маршруты 2/3/4 endpoint
и отдельная host namespace preparation прошли. Production `53027e6b…` / исходники
`ac71fc83` установлены на Flip и Odin; [хеши и сохранность состояния](../evidence/native-groups-20261026/README.md).
Сохранены существующие пакеты/история/профили; native progress кабинетов остаётся временным,
Dreamcast Online сохраняет свой прежний protected VMU archive. Остальные платформы
не получают четыре места автоматически: PS2/BBA и другие native transports требуют
собственного группового маршрута. Предел семейства не объявляется сертификатом каждой игры.
