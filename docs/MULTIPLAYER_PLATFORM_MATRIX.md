# TrainerOS — multiplayer platform matrix

Проверяем платформы **по соседним семействам, от старых к новым**. В эту таблицу попадают только обсуждённые группы. Существование ARM64-ядра или отметка NetPlay в Libretro **не доказывает**, что сетевой матч работает на ArmadaOS / Flip 2 / Odin 2.

## Согласованная общая политика — 12 октября 2026

- **Universal Remote Play — временная универсальная затычка для платформ без полноценного мультиплеера**: даёт играть вместе, пока для конкретной системы не будет сделан или подключён её нормальный NetPlay / Link / LAN. Он **не считается выполнением целевой поддержки** платформы. После появления настоящего маршрута Remote Play может оставаться опцией для тех, кому он нравится. **Это требование к будущей реализации, не готовая функция.**
- В Remote Play **одна игра выполняется на устройстве хозяина**; гостю передаются изображение и звук, от него приходит управление назначенным виртуальным контроллером. Это **не NetPlay/синхронизация двух эмуляторов**. Прогресс и сохранения принадлежат хосту; доступ и управление должны быть явно согласованы.
- Там, где работают штатные механизмы эмулятора, используем их: **shared-console NetPlay**, **связь независимых виртуальных консолей (Link / локальная беспроводная сеть)** или **собственная сеть игры (LAN / Online)**. Не подменяем один тип другим.
- **Hotseat / передача контроллера** — отдельная возможность, если игровая механика позволяет. Поочерёдные ходы через два штатных порта P1/P2 не равны передаче одного P1.
- Специальные устройства ввода (paddles, keypad, analog и т. п.) проверяются отдельно от обычных цифровых геймпадов.
- **Приоритет** — существующие нормальные мультиплеерные механизмы популярных систем, параллельно универсальная временная поддержка через Remote Play. **Позже** — собственный NetPlay для простых/редких ядер, где готового решения нет. Не начинать новый протокол/ядро только потому, что в таблице стоит «нет», без отдельного решения владельца.
- Статус NetPlay в документации ядра — лишь кандидат; перед включением в TrainerOS нужны реальная совместимость сборок ARM64, ввод каждого игрока, связь, Home/Exit и сохранность данных. Разные сети — отдельная проверка.
- Эта таблица **не является разрешением Codex самостоятельно изменять эмуляторы или писать сетевой код**. Каждое следующее семейство обсуждается отдельно.

**Опорные данные:** `data/rom-platforms.json`, `packaging/emulators/arm64-baseline.json`, `docs/EMULATOR_STANDARD.md`; таблицы возможностей ядер — документация Libretro: [Stella](https://docs.libretro.com/library/stella/), [GearColeco](https://docs.libretro.com/library/gearcoleco/), [FreeChaF](https://docs.libretro.com/library/freechaf/), [ProSystem](https://docs.libretro.com/library/prosystem/).

## Группа 02 — ранние 8-битные компьютеры (предварительная классификация)

В реестре — **22 ID**. Объединены по семействам железа/ядер, чтобы не проверять одинаковый сетевой механизм несколько раз. Базовый сценарий здесь — **один виртуальный компьютер с двумя локальными игроками** (два джойстика, джойстик + клавиатура, две разные раскладки на клавиатуре или игра по очереди). Связь двух физических компьютеров через модем/последовательный порт **не считается общей возможностью** семейства: исследовать отдельно только для конкретных игр и реализованных в эмуляторе периферийных устройств.

| --- | --- | --- | --- | --- |
| Apple II / `apple2` | AppleWin | Клавиатура, игровые контроллеры/paddles; количество зависит от игры и адаптера | ? (в таблице функций не указан) | Исследовать штатную синхронизацию/ввод; Remote Play временно |
| Commodore PET / `pet`, VIC-20 / `c20`, C64 / `c64`, C128 / `c128`, Plus/4 / `cplus4` | VICE: `vice_xpet`, `vice_xvic`, `vice_x64`, `vice_x128`, `vice_xplus4` | Клавиатура и обычно до двух джойстиков для совместимых моделей/игр; некоторые C64 поддерживают дополнительные порты через адаптеры | Нет | Общая VICE-ветка; исследовать рабочую альтернативу позже; сейчас Remote Play |

| Amstrad CPC / `amstradcpc` | Caprice32 (`cap32`) | Два джойстика; есть варианты сопоставления второго ввода с клавишами | Да | Проверить RetroArch NetPlay с двумя независимыми игроками |

**Статус группы:** предложенные маршруты, **без тестов на ArmadaOS и без решения о разработке новых ядер**. «Да» = только функция в таблице Libretro. Для компьютеров **раскладка клавиатуры и получение ввода от второго пользователя — отдельная приёмка**. Все 22 ID перечислены один раз.

**Источники:** реестр TrainerOS `data/rom-platforms.json` и [Libretro: VICE](https://docs.libretro.com/library/vice/), [Atari800](https://docs.libretro.com/library/atari800/), [EightyOne](https://docs.libretro.com/library/eightyone/), [Fuse](https://docs.libretro.com/library/fuse/), [b2](https://docs.libretro.com/library/b2/), [blueMSX](https://docs.libretro.com/library/bluemsx/), [Caprice32](https://docs.libretro.com/library/caprice32/), [AppleWin](https://docs.libretro.com/library/applewin/), [ep128emu](https://docs.libretro.com/library/ep128emu/), [BK](https://docs.libretro.com/library/bk/), [Theodore](https://docs.libretro.com/library/theodore/), [QUASI88](https://docs.libretro.com/library/quasi88/). Неустановленные возможности оставлены «?», а не объявлены неподдерживаемыми.
