# NetPlay: выбор relay и разные сборки — 23 октября 2026

По поручению владельца общий NetPlay должен работать без привязки к паре
Flip/Odin. Владельцы изменений — S03 (запуск) и S07 (сеть), S06 хранит выбор
создателя лобби; путь F04/E07. Подбор совместимого комплекта для Steam Deck
выполняется после появления устройства. Пользовательские игровые проверки
владелец проводит самостоятельно и сообщает найденные проблемы.

## Выбор региона

Для Online-семейства RetroArch в **GameHub → Lobby → Lobby options → Relay**
доступны Automatic, Europe/Madrid, North America/New York, South America/São Paulo
и Asia/Singapore. Это регионы [штатного списка RetroArch](https://github.com/libretro/RetroArch/blob/master/network/netplay/netplay_frontend.c).
PSP/Dolphin и другие отдельные сетевые механизмы сохраняют собственные серверы
и способы подключения; выбор RetroArch relay к ним не применяется.

По умолчанию используется Automatic. После Start каждый играющий участник
обращается к штатному HTTP directory Libretro и измеряет три TCP-подключения к каждому
региону. Время DNS исключено из измерения TCP; комнаты/игры во время измерения
не создаются. Оценка — медиана плюс разброс трёх подключений. Хозяин выбирает
доступный всем регион с наименьшей худшей оценкой; при равенстве — с наименьшей
суммой. Зрители в выборе не участвуют. Это оценка задержки/краткого разброса,
не замер пропускной способности и не обещание убрать задержку между континентами.

Результаты идут через существующий приватный Lobby runtime signal, привязанный
к участнику, ticket и generation. Peer передаёт только оценки фиксированных
регионов: он не задаёт адреса для подключения других устройств. Хозяин получает
endpoint из собственного ответа directory. Отмена, новая сессия и изменение
контекста прекращают старые измерения. Нет постоянной фоновой проверки.

Только хозяин может выбрать регион вручную до запуска. Изменение сбрасывает
подготовку/Ready и сохраняется в состоянии комнаты; обычный рестарт комнаты
сохраняет выбор. Идущий матч не переключается. В ручном режиме измеряется только
указанный регион, без скрытой замены на другой. Если нет общего доступного
региона или не получены ответы всех игроков за ограниченное время, запуск
завершается понятной ошибкой с предложением повторить или сменить регион.

Старый внутренний путь GameParty вне обычного GameHub Lobby также больше не
закрепляет Madrid, но располагает только измерениями хозяина. Пользовательский
маршрут Lobby использует измерения всех игроков.

## Разные бинарники

`sameMultiplayerGame` больше не требует совпадения полей `runtime` и `core`
(SHA256 бинарников) для профилей `runtime.*`. Разные ARM/x86 бинарники сами по
себе не запрещают приглашение, подготовку и попытку подключения. При обычных
раздельных pads различие списка дополнительных controller modes тоже не мешает.
Конкретный pass-controller режим по-прежнему требует локальной поддержки.

Сохранены совпадение режима/ядра по ID профиля, содержимого игры, firmware,
настроек, протокольных полей и правил контроллеров. Проверки совместимости
внутри самих эмуляторов не отключались. Это разрешение подключения разных сборок,
а не утверждение их совместимости: набор эмуляторов для Steam Deck ещё не выбран.

Локальные manifests и контроль целостности установки не ослаблены. В RetroArch
отдельно фиксируется **локальный** runtime/core при подготовке: замена файлов
на этой портативке перед запуском отклоняется независимо от бинарника друга.
Правила личных сохранений и семантического доступа адаптеров не изменены.
Отдельная возможность входа в уже запущенную игру определяется проверенной локальной
установкой: сведения о бинарниках друга не дают ей отсутствующих возможностей.

## Проверки и поставка

ARM64 сборка оболочки завершена. Успешно прошли профильные CTest suites:
`netplay_relay`, `retroarch`, `lobby`, `game_party`, `runtime_multiplayer`,
`standalone`, `social`, `rmg_netplay`, `flycast_netplay`. После последних изменений
повторены затронутые `netplay_relay`/`runtime_multiplayer`; неизменённые suites
повторно не гонялись. Устаревшие ожидания одинаковых бинарников заменены проверками
несовместимых настроек. Проверка Hotseat использует актуальную навигацию вправо
во вторую колонку и сохраняет проверку возврата фокуса после передачи контроллера.

Проверены выбор по всем участникам, исключение недоступного региона, ручной выбор
без подмены, чужие/повторные/некорректные отчёты, отмена, очистка после выхода,
сброс Ready и сохранение выбора, меню хозяина, ARM/x86 admission и сохранение
локальных ограничений. Два экземпляра production selector обращались к тестовому
HTTP-каталогу и выполнили 24 настоящих TCP-подключения, без запуска игры.
Переносимые исходники: export/check прошли, 32 semantic + 170 runtime файлов.

Production selector также выполнен на Flip/Odin против публичных серверов.
