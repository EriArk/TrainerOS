# NetPlay: исправление профиля PS1 и задержек Wi-Fi — 23 октября 2026

**Продолжение:** [исправление общего моста, linked rollback и кэшей](NETPLAY_PLATFORM_REPAIR_2026_10_23.md)
установлено позднее в тот же день. Оно также устраняет указанный ниже сбой registry/export.

Владелец сообщил о фризах Neo Geo и сильных фризах/потере связи PS1;
Remote Play сейчас не является задачей. Компоненты: S03 runtime, S07 network,
потребители S06 Lobby и S08 input; существующий цикл F04 и личные сохранения
сохранены. Проверки разрешены на Flip/Odin. Работа изолирована в ветке
`codex/netplay-stability`, без изменений незавершённых Apps/SDK/avatar работ.

## Установленные исправления

- В приватном профиле PCSX ReARMed ошибочный ключ
  `pcsx_rearmed_threaded_rendering` заменён на
  `pcsx_rearmed_gpu_thread_rendering=disabled`. Установленное ядро содержит
  только второй ключ; первое значение игнорировалось и оставляло default `auto`.
  Идентификатор профиля изменён с `pcsx-two-digital-private-bios-no-sram-v1`
  на `v2`: смешанная пара старого и исправленного профилей не допускается.
- Для общей семьи RetroArch rollback включена штатная адаптация задержки
  ввода: minimum 0, range 6 кадров. Прежние обычные конфигурации обоих устройств
  содержали 0/0, а подготовка сессии не задавала собственные пределы.
  Это диапазон адаптации по native LATENCY, а не постоянные шесть кадров.
  Независимые handheld/netpacket и отдельный PS2 candidate исключены.
  Это исходная настройка для дальнейших замеров, не доказательство устранения
  всех фризов. Механизм эмуляции/сетевой протокол не переписывался.
- Добавлен поддерживаемый NetworkManager default `wifi.powersave=2`.
  Установщик сохраняет предыдущий собственный файл, перегружает только
  конфигурацию NM и применяет текущему интерфейсу `iw ... power_save off`
  только при значении профиля `default`. Явные значения профиля сохраняются;
  переподключения Wi-Fi нет. На Flip default был включён, на Odin уже был
  явный `disable`. После установки оба интерфейса показывают `off`.

Исходники: [подготовка сессии](../src/integrations/adventure/retroarch/RetroArchNetplay.cpp),
[проверки](../tests/RetroArchTests.cpp),
[системный установщик](../packaging/integrations/install-network-latency.py).
Обычные core options, карты памяти и графические предпочтения не переписываются.
Системный installer пока выполняется отдельно; интеграция в общий установщик
дистрибутива не заявлена.

Оба устройства: Armada `20261017.64207e6`, RetroArch Flatpak `1.22.2`.

- PCSX ReARMed: `25bfeb6336d7ef573903775fe53733af974c90edd268cf4fb9afa497e188609d`.
- FBNeo: `ffb37315a609317e1a00bf32c0e3d66c5a848d052d1260f4ab7f42da0f9fb9c3`.

После сравнения исходное состояние было восстановлено, затем отдельно
установлена поддерживаемая настройка. Это ограниченное измерение одного AP,
не замер WAN или длительности игровых фризов.

ARM64 production build прошёл. После явного `BUILD_TESTING=ON` и компиляции
изменённых исходников RetroArch suite: **60 passed, 0 failed**. Проверены
правильный ключ, отказ старому PS1 token, 0/6 только в приватной сессии,
сохранность исходной конфигурации и удаление временных карт/BIOS.
Первый запуск 61 старого теста при выключенном BUILD_TESTING не засчитывается.

Одинаковая новая оболочка установлена и перезапущена на обоих устройствах:
`d52144f9bdb2cf5abafe0db1dd8a8423a4f56d18652a778ff7edf2d2967ac4e7`.
Зависимости проверены из каталога установки с сохранением `$ORIGIN`.
Предыдущий бинарник сохранён в приватном каталоге доставки.

Парный диагностический CTR US использовал **новый production код подготовки**,
личные ROM только для чтения и отдельные BIOS/карты. На обоих прочитаны
`v2`, правильная GPU option и range 6. Native RetroArch подтвердил P1/P2,
показывал меню и меняющиеся сцены; ошибок desync/CRC до управляемой остановки
в журнале не было. Первый прямой fullscreen запуск вызвал повторные resize
на Odin: он не годится для оценки плавности. Повторный оконный стенд исключил
эту особенность прямого запуска; наблюдался отдельный кадр с 57,10 FPS на Odin.
Одиночный FPS snapshot не является распределением frametime или доказательством
плавного матча. Это не новая проверка обычного Lobby, физических геймпадов,
звука или двух независимых интернет-сетей. Личные данные не переносились.

Аналогичный оконный запуск Metal Slug 3 / FBNeo подтвердил P1/P2 и приватный
range 6 на обоих устройствах; просмотрены кадры загрузки, на одном снимке Odin
59,51 FPS. Полный игровой матч Neo Geo не проверен. После каждого сценария
Owned RetroArch остановлен, production temporary directory удалён;
SHA256 всех 90 Flip / 1110 Odin файлов ограниченного baseline
(`cfg/opt/rmp/srm/sav/mcd` в RetroArch data) остались прежними.
После доставки текущие оболочки имеют одинаковый SHA256 и 0 обнаруженных
QML ошибок в своих журналах; обе портативки оставлены с громкостью 0.

Переносимая копия изменённого runtime файла и его SHA256 обновлены.
Общий `check-adapter-knowledge.py` остаётся красным из-за существовавшей
ссылки `runtime.dolphin.gc.v1` на удалённый `MULTIPLAYER_PREPARATION.md`.
Полный exporter также обнаруживает старое рассогласование других снимков;
несвязанные копии этим исправлением не перезаписывались.

## Iris и оставшиеся условия

Свежий аппаратный probe подтвердил прежние дефекты геометрии Flip и
запрошенного IDR на обоих устройствах. [Точная запись](ARMADA_IRIS_ENCODER.md).
Iris не обслуживает обычную эмуляцию RetroArch NetPlay; постоянная безопасная
доставка драйвера остаётся незавершённой. Горячая выгрузка Odin не повторялась.

Остаются: воспроизведение конкретных игр/участков владельца, длительные
матчи PS1/Neo Geo, frametime/rollback и разрыв связи под контролируемым jitter,
обычный Lobby и отдельные интернет-сети. Не закрывать R029 или заявленный
пользователем дефект по этому ограниченному запуску. Публичный HTTP directory
для существующего `madrid` ответил корректно; отказ отдельного HTTPS запроса
не был принят за доказательство неисправности используемого HTTP маршрута.

## Обновление и откат

При обновлении PCSX сравнить [точные upstream options](https://github.com/libretro/pcsx_rearmed/blob/c8816799b50388e61cfe237fe2cdbb7d8175f20a/frontend/libretro_core_options.h),
действительные core/runtime hashes и поведение сериализации. Механизм задержки:
[официальная документация RetroArch](https://docs.libretro.com/development/retroarch/netplay/).
NetworkManager: [powersave enum](https://networkmanager.pages.freedesktop.org/NetworkManager/NetworkManager/settings-802-11-wireless.html).

Для отката оболочки закрыть игры, восстановить сохранённый бинарник и
перезапустить её. Личные карты не мигрировались. Для Wi-Fi восстановить прежний
`90-traineros-network-latency.conf` из `/var/lib/traineros/network-latency-before`
либо удалить только этот файл, если marker `recorded` содержит `absent`, затем
`nmcli general reload conf`. Для немедленного возврата прежнего Flip режима
использовать `iw ... power_save on`; Odin до изменения уже был off.
Явный per-connection powersave остаётся пользовательским способом переопределения.
