# SOCIAL-67 — Discover и выход из комьюнити

17 октября 2026. Владелец принял управление SOCIAL-66 и согласовал следующий
экран по #219. Поставка и проверки фиксируются отдельно ниже.

## Принятая композиция

Компактный поиск с People / Communities; ссылки-приглашения в том же поле.
На стартовом экране — горизонтальная лента Recently Together (около шести
аватаров, ник, последняя совместная игра/время, «Все»), ниже три карточки
популярных комьюнити TrainerOS в ряд. Поиск заменяет эти блоки результатами;
очистка возвращает стартовый экран. Человек открывает общий профиль,
комьюнити — предпросмотр с явным Join. B сохраняет запрос и позицию.
L2/R2 переключают разделы Social. Тёплая поверхность, тихий узор, аккуратные
рамки и общие отступы; без больших кнопок категорий и технических настроек.

Дополнение владельца: выход из комьюнити и удаление своего комьюнити должны
быть доступны в коротком контексте/информации. Подтверждение точного объекта,
права Fluxer и обязательная дополнительная проверка владельца сохраняются.
Это разрешение реализовать функцию, не удалять существующие комьюнити.

## Контракты Fluxer и фактическая доступность

Официальный upstream проверен 17 октября, revision
`1f47e70ebee28ab744022d20e1ae00c61f249c43`:

- [Discovery schema](https://github.com/fluxerapp/fluxer/blob/1f47e70ebee28ab744022d20e1ae00c61f249c43/packages/schema/src/domains/guild/GuildDiscoverySchemas.ts):
  native discovery принимает `tag`, `sort_by=member_count`, query/limit/offset,
  возвращает `guilds`, `total`, `custom_tags`, banner/icon и количество участников.
  TrainerOS запрашивает и проверяет точный `traineros-v1`; pinned-маркер
  присоединённого комьюнити не является публикацией в публичный discovery.
- На двух текущих тестовых аккаунтах GET discovery вернул **200, total=0**.
  Это подтверждает доступность API, но не наличие опубликованных комьюнити.
  Карточки с заполнением проверяются отдельно синтетическими UI-данными.
- Поиск людей использует знакомые identities и официальный GET по точному ID.
  Публичный fuzzy/tag-to-profile API не найден. Владелец отдельно согласовал
  явную заявку по полному `username#1234`; такой результат не выдаётся за профиль.
- Ссылка/код сначала читаются через GET invites. Join — отдельное нажатие.
  Публичные карточки вступают через POST discovery join, приглашения — через
  POST invites. Обычный просмотр не меняет членство.
- [Guild member controller](https://github.com/fluxerapp/fluxer/blob/1f47e70ebee28ab744022d20e1ae00c61f249c43/fluxer_api/src/api/guild/controllers/GuildMemberController.ts):
  DELETE `/users/@me/guilds/:id` покидает комьюнити; не запрашиваем удаление сообщений.
- [Guild base controller](https://github.com/fluxerapp/fluxer/blob/1f47e70ebee28ab744022d20e1ae00c61f249c43/fluxer_api/src/api/guild/controllers/GuildBaseController.ts):
  POST `/guilds/:id/delete` требует владельца и sudo. Перед действием перечитываем
  guild; подтверждение хранит точный ID. Пароль / TOTP / backup code передаются
  только после требования провайдера, через скрытый ввод; в черновики не попадают.
  Security-key-only проверка остаётся в официальном Fluxer, без обхода.

Recently Together v2 сохраняет последнее название/время игры по аккаунту.
`playing` наступает после подтверждений успешного запуска первоначальных игроков;
нужны game, ticket, connected player seat. Ожидание, зрители и незавершённый
live admission исключены. История v1 знала лишь встречи в комнате и не мигрируется
в доказанные совместные игры. Отложенный переход зрителя в игрока не считается
реализованным этим изменением.

## Реализация, проверки и поставка

Поиск/API вынесены в [FluxerDiscover.cpp](../src/integrations/social/FluxerDiscover.cpp),
навигация — в [SocialDiscover.cpp](../src/features/social/SocialDiscover.cpp),
экран — в [DiscoverPane.qml](../src/qml/DiscoverPane.qml). Общий профиль,
клавиатура, история разговоров и действия Fluxer повторно используются.
На низкой доступной высоте уменьшаются баннеры и интервалы; имена, игра/дата
и три community-карточки остаются видимыми. После запроса членства показывается
ожидание; сетевые ошибки не убирают комьюнити из локального списка.

- Social: **174 passed**, без провалов/пропусков; Lobby: **45 passed**, три
  прежних пропуска. Проверены права и точный ID, пароль/MFA, отказ/неопределённый
  ответ без автоматического повтора удаления, сохранение чужих каналов/личек,
  поздний поиск, bare invite, неизвестный тег, preview и явный Join,
  реальные игровые условия Recently Together и разделение аккаунтов.
- QML-сценарии Discover и прежнего Messages/Communities прошли. Проверены
  заполненный/пустой экран, 1600×900 и 960×540, поиск, профиль, предпросмотр,
  «Все», контекст владельца и подтверждение. `qmlWarnings=0` в обоих отчётах.
  Windows fixture-runner также выводит два Qt `Model size of -1` сообщения
  в обоих сценариях; их источник отдельно не локализован. Нулевой QML-счётчик
  не означает отсутствие вообще любых stderr.
- Сборка установлена на **Odin и Flip**. Проверены одинаковый SHA-256 работающих
  файлов, исходники ARM по манифесту, целостность баз и неизменные игровые сессии.
  Перед установкой нет активных эмуляторов; сохранены резервные копии приложения
  и базы. Odin остаётся с громкостью 0.
  SHA-256 поставленной сборки:
  `ed323177be92220e0a096b21211a378f46fed5bdad42908cece5a3430d76d994`.
- На обеих портативках просмотрен настоящий Discover. На одном комьюнити
  устройство участника показывает Leave, владельца — Delete. Открыты правильные
