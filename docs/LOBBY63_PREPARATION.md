# LOBBY-63 — подготовка, запуск и возврат

Согласование владельца 17 октября 2026: [#211](https://github.com/EriArk/TrainerOS/issues/211),
[#212](https://github.com/EriArk/TrainerOS/issues/212) и уточнения в чате.
Документ разделяет реализацию, установленную сборку и проверку на устройствах.

## Реализация текущего прохода

- `LaunchPresentation` собирает состояния существующих владельцев запуска:
  `LaunchPreparation`, `AdventureLaunchController`, `LobbyRuntime` и
  `RuntimeMultiplayer`. Он не запускает процессы самостоятельно. `LaunchPanel`
  общая для одиночной игры и сетевого запуска; согласие на выход имеет приоритет.
- Ready больше не запоминается до проверки. После переключения активной комнаты
  сначала выполняется подготовка, затем пользователь явно нажимает Ready.
  Незавершённое голосование блокирует подготовку прежней игры.
- Последняя коррекция владельца: все Ready лишь открывают владельцу крупную
  Start справа в карточке игры. Автозапуск отменён; модель повторно проверяет
  готовность, владельца, игру и состав непосредственно при нажатии Start.
- По дополнительному уточнению владельца Ready сразу показывает `Confirming…`
  с крутилкой и блокирует повторное нажатие до ответа. Затем доступна Not ready.
  Ожидание ограничено, снимается при ошибке/смене контекста. Промежуточный снимок
  комнаты не сбрасывает отправленное согласие, пока подтверждение ещё идёт.
- `LobbyImportController` использует `FilePickerController`, `AdventureAdapter`
  и `LibraryRepository`. Общая `runtimeIdentity` обслуживает обычное обнаружение
  и проверку выбранного файла; peer-метаданные не задают исполняемый файл/команду.
  Файл регистрируется на выбранном пользователем месте без копирования или
  перезаписи сохранений. Ошибка, отмена и устаревший контекст до записи не добавляют игру.
- Для отсутствующей игры доступен импорт из карточки и своей аватарки. Индикатор
  проверки отделён от Preparing/Ready. Успешная регистрация обновляет библиотеку
  и запускает повторную проверку; обычная ошибка сама по кругу не повторяется.
- Remote Play гостю ROM не нужен; локальный файл проверяется только у хоста.
  Завершение и возврат используют существующий защищённый жизненный цикл.

Старый жёлтый круг `HOME` для отложенных приглашений отклонён владельцем и удалён.
Сами приглашения остаются в уведомлениях. Верхние вкладки и аватары участников
этой коррекцией не меняются; новый вид свёрнутого приглашения требует согласования.

Реализация и финальная коррекция Ready/Start установлены на Odin/Flip.
Парный запуск NES Pong и штатный возврат проверены. Галочки ниже означают
реализацию общего механизма; конкретные проверки и оставшаяся приёмка — в конце.

## Путь игрока

- [x] Подтверждённая игра/режим запускает локальную проверку автоматически.
  Обычной кнопки Prepare нет; Ready доступна после успешной подготовки.
- [x] Preparing под аватаркой по-прежнему означает «не нажал Ready». Техническая
  проверка показывается отдельным маленьким индикатором; ошибка/подробности
  доступны через свою аватарку и карточку игры. Чужие пути/библиотеки не раскрывать.
- [x] Нет подходящего локального содержимого — точная причина и «＋ Импортировать»
  через существующий FilePickerController и библиотечную регистрацию. Неверный
  файл/отмена не меняют библиотеку и сохранения. Успех возвращает в ту же комнату
  и возобновляет проверку. Remote Play гостю локальный ROM не требуется.
- [x] Другая запущенная игра сохраняет существующий безопасный путь подтверждения
  выхода. Автоматическая подготовка не закрывает её, не заменяет сохранение,
  не даёт согласия на передачу содержимого и не подключает голос.
- [x] Ready всех текущих игроков открывает Start хозяину справа в карточке игры.
  Нажатие Start запускает игру ровно один раз. Зрители исключены из проверки.
  Время сбора само игру не запускает. Прежний автоматический запуск заменён.
- [x] Смена игры/режима/мест/состава/владельца и устаревшие ответы не могут запустить
  предыдущий вариант. После настоящей ошибки — явный Retry, без циклов попыток.
- [x] Выход возвращает в ту же комнату с сохранёнными игрой, чатом и членством;
  Ready вышедшего снимается. Завершение сессии у остальных зависит от runtime.

## Окно запуска — новое уточнение владельца

- [x] Поверх затемнённого интерфейса средняя всплывашка в стиле TrainerOS:
  игровой фон/иллюстрация, название, крутилка, текущий этап, кнопка отмены.
  Использовать существующий LaunchPanel и общие службы, не второй запускатель.
- [x] Этапы берутся из реальных событий: проверка, подготовка подключения,
  ожидание игроков, запуск процесса, передача управления. Никаких выдуманных
  процентов или сменяющихся по таймеру названий работ.
- [x] Отмена отменяет текущую операцию и возвращает в комнату; поздние ответы
  игнорируются. При безопасном завершении операции показывать «Отменяем…».
  После передачи управления запущенной игре действует обычный Game Options/exit,
  а не принудительное убийство процесса кнопкой сплеша.
- [x] Запрос сохранения/другого согласия виден над сплешем или временно заменяет
  его; крутилка не закрывает действие, которого ждёт система.
- [ ] Необязательная компактная подсказка по управлению только при наличии
  проверенных данных. Данные локальные/кешированные, получение подсказок не
  задерживает запуск. Сейчас подтверждённого импорта этих данных нет, поэтому
  блок отсутствует. Раскладку конкретной игры не угадывать; добавление данных позже.
- [x] Владелец уточнил: общее окно для всех запусков, включая одиночные.
  Весь ранее согласованный блок выполняется вместе, без остановки на одном сплеше.

## Что подтверждено перед реализацией

До этого прохода в исходниках уже были `LaunchPanel.qml`, `AdventureLaunchController`,
`LaunchPreparation`, `LobbyRuntime` и автоматическая попытка в
`SocialController::reconcileLobbyPreparation`. Панель показывала только
«Just a moment». В этом проходе доработаны существующие службы, второй
владелец запуска не добавлялся.

В [официальном WebAPI ScreenScraper](https://www.screenscraper.fr/webapi2.php)
описаны типы `controls` (форматированный текст), `trucsetastuces` и PDF-мануалы.
Это подтверждает наличие таких категорий данных, но не их заполненность и формат
ответа `jeuInfos` для каждой игры. Текущий `ScreenScraper::parseGame` их не сохраняет.
Перед импортом проверить реальный ответ; безопасно нормализовать текст, хранить
источник и не смешивать кнопки оригинальной консоли с текущими привязками геймпада.
Мануал не превращается автоматически в краткие подсказки.
