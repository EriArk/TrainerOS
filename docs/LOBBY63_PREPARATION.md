# LOBBY-63 — подготовка, запуск и возврат

Согласование владельца 17 октября 2026: [#211](https://github.com/EriArk/TrainerOS/issues/211),
[#212](https://github.com/EriArk/TrainerOS/issues/212) и уточнения в чате.
Документ фиксирует следующий блок; галочки ниже не означают установленную сборку.

## Путь игрока

- [ ] Подтверждённая игра/режим запускает локальную проверку автоматически.
  Обычной кнопки Prepare нет; Ready доступна после успешной подготовки.
- [ ] Preparing под аватаркой по-прежнему означает «не нажал Ready». Техническая
  проверка показывается отдельным маленьким индикатором; ошибка/подробности
  доступны через свою аватарку и карточку игры. Чужие пути/библиотеки не раскрывать.
- [ ] Нет подходящего локального содержимого — точная причина и «＋ Импортировать»
  через существующий FilePickerController и библиотечную регистрацию. Неверный
  файл/отмена не меняют библиотеку и сохранения. Успех возвращает в ту же комнату
  и возобновляет проверку. Remote Play гостю локальный ROM не требуется.
- [ ] Другая запущенная игра сохраняет существующий безопасный путь подтверждения
  выхода. Автоматическая подготовка не закрывает её, не заменяет сохранение,
  не даёт согласия на передачу содержимого и не подключает голос.
- [ ] Ready всех текущих игроков запускает игру ровно один раз. Зрители исключены;
  отдельного Start у хозяина нет. Время сбора само игру не запускает.
- [ ] Смена игры/режима/мест/состава/владельца и устаревшие ответы не могут запустить
  предыдущий вариант. После настоящей ошибки — явный Retry, без циклов попыток.
- [ ] Выход возвращает в ту же комнату с сохранёнными игрой, чатом и членством;
  Ready вышедшего снимается. Завершение сессии у остальных зависит от runtime.

## Окно запуска — новое уточнение владельца

- [ ] Поверх затемнённого интерфейса средняя всплывашка в стиле TrainerOS:
  игровой фон/иллюстрация, название, крутилка, текущий этап, кнопка отмены.
  Использовать существующий LaunchPanel и общие службы, не второй запускатель.
- [ ] Этапы берутся из реальных событий: проверка, подготовка подключения,
  ожидание игроков, запуск процесса, передача управления. Никаких выдуманных
  процентов или сменяющихся по таймеру названий работ.
- [ ] Отмена отменяет текущую операцию и возвращает в комнату; поздние ответы
  игнорируются. При безопасном завершении операции показывать «Отменяем…».
  После передачи управления запущенной игре действует обычный Game Options/exit,
  а не принудительное убийство процесса кнопкой сплеша.
- [ ] Запрос сохранения/другого согласия виден над сплешем или временно заменяет
  его; крутилка не закрывает действие, которого ждёт система.
- [ ] Необязательная компактная подсказка по управлению только при наличии
  проверенных данных. Данные локальные/кешированные, получение подсказок не
  задерживает запуск. Без данных блок скрыт. Раскладку конкретной игры не угадывать.
- [ ] Область применения (все запуски или только Lobby) уточняется с владельцем.

## Что подтверждено перед реализацией

В исходниках уже есть `LaunchPanel.qml`, `AdventureLaunchController`,
`LaunchPreparation`, `LobbyRuntime` и автоматическая попытка в
`SocialController::reconcileLobbyPreparation`. Панель пока показывает только
«Just a moment»; отдельные подготовительные этапы ещё не дают ей прогресс.
Существующую попытку подготовки доработать, не добавлять второй координатор.

В [официальном WebAPI ScreenScraper](https://www.screenscraper.fr/webapi2.php)
описаны типы `controls` (форматированный текст), `trucsetastuces` и PDF-мануалы.
Это подтверждает наличие таких категорий данных, но не их заполненность и формат
ответа `jeuInfos` для каждой игры. Текущий `ScreenScraper::parseGame` их не сохраняет.
Перед импортом проверить реальный ответ; безопасно нормализовать текст, хранить
источник и не смешивать кнопки оригинальной консоли с текущими привязками геймпада.
Мануал не превращается автоматически в краткие подсказки.

## Проверки и доставка

- [ ] Целевые тесты отмены/устаревших ответов/повторного запуска/смены комнаты,
  безопасного импорта и сохранений; не повторять остальные пройденные маршруты.
- [ ] Визуальный осмотр обычной подготовки, запуска, отмены и ошибки на обоих
  доступных устройствах; touch/controller и работа без подсказок.
- [ ] Парный запуск уже реализованного режима и возврат. Другие семейства и
  физические/отдельные сети остаются отдельной приёмкой.
- [ ] PROJECT_STATUS, CHANGELOG, установленная сборка и commit/push.

Local без Fluxer, пробуждение к напоминанию, новые multiplayer-механизмы,
PS3/Switch и другие вкладки в этот блок не входят.
