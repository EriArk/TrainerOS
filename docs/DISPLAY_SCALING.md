# DISPLAY-18 — масштаб интерфейса и граница фона Home

16 октября 2026. Продолжение #193/#156, с сохранением отдельного объёма #159.
Последнее указание владельца: нормальный скейлинг с настройками; игровой фон
только на всей карточке игры. Владелец одобрил направление композиции на
IMG_1047; это не физическая приёмка всех устройств/режимов.

## Что изменено

- Settings → Appearance: Display profile, Interface size (75–150%, шаг 5%),
  Reset interface size. Изменения применяются сразу и сохраняются на устройстве.
  Стрелки/А и прямые кнопки −/+ используют одну службу настроек.
- Общая плотность задаёт размер рамки, текста, кнопок и shell popup; app controls
  и invitation/player bubbles используют ту же величину. Exit overlay уже
  использует общие логические границы. Эмулятор и его разрешение не меняются.
- Геометрия берётся из логического QScreen и доступного окна, Qt применяет DPR
  при растеризации. Живая сцена Qt Quick не превращается в растянутую текстуру
  960×540: её логические границы = размер окна / плотность, пропорции свободные.
  При смене размера окна компоненты получают новые доступные границы.
- Handheld использует короткую сторону логического дисплея / 540, TV / 480;
  пользовательский процент меняет эту плотность. Auto пока следует системной
  плотности Qt. Разрешение само по себе не объявляет устройство телевизором.
- Минимальное доступное пространство 800×450 ограничивает увеличение; настройка
  сообщает Limited by window. Значение пользователя сохраняется для большего окна.
  Строки и категории настроек прокручиваются вместо уменьшения шрифтов. После
  перестроения делегатов прокрутка ждёт positioningComplete, поэтому выбранная
  строка остаётся видна и на реальном Qt/Vulkan устройстве.
- Home снова использует обычную бумагу/корпус снаружи карточки. Иллюстрация первого
  запуска и полупрозрачный игровой кадр находятся только внутри всей карточки.
  Убраны отдельные увеличители текста Home/adapter, сохранены круглая A и медальоны.
  Команда адаптера размещается после прогресса, без наложения подписей.

Механизм заменяет мелкие фиксированные размеры после `87bb989` и полноэкранную
иллюстрацию [Home17](https://github.com/EriArk/TrainerOS/blob/c6aaac25ba4f55262f3f6418e8d29cac7cdc9aec/docs/HOME17_VISUAL_DELIVERY.md), поставленную в
[d6135f3](https://github.com/EriArk/TrainerOS/commit/d6135f3).

## Проверки исходников и хост-сборки

- Windows Qt 6.11.1: сборка traineros и 44 InteractionTests, без падений.
  Проверены плотность 720p/1080p/4K, учёт логического DPR, 16:10, Auto/TV,
  ограничения размера, сохранение/сброс и семантический фокус настройки.
- Home smoke: первый запуск, whole-card backdrop/родитель иллюстрации, badges,
  party и защищённый запуск/возврат из изолированного fixture — qmlWarnings=0.
- Experience smoke: независимые адаптеры и маршрут, 1280×800, окно 3840×2160,
  живое изменение размера, Settings в минимальном окне — qmlWarnings=0.
- Отдельный offscreen-дисплей 3840×2160 с logicalDpi=192: Home smoke прошёл,
  кадр окна 1920×1080 logical имеет 3840×2160 физических пикселей.
  Это имитация DPI/вывода на хосте, не тест настоящего TV.
- Исходные выводы/кадры остаются локально в build/home18-*; устройства проверены
  отдельно. Использованы официальные [Qt high-DPI](https://doc.qt.io/qt-6/highdpi.html)
  и [Screen](https://doc.qt.io/qt-6/qml-qtquick-screen.html) контракты.

## Установка и проверка Odin

Armada уже обновлена до `20261015.01e50d4` и перезагружена в предыдущем проходе;
обновление не повторялось. Нативная ARM64 Release-сборка Qt 6.11.2 установлена
с резервной копией прежнего бинарника и базы, после проверки отсутствия игры.
SHA256 запущенного процесса совпал с собранным бинарником:
`1969150f39ab703066278512ba9cd3780b7541bc482f84e9ef33a925eea9ba2c`.
Все изменённые исходники в ARM-сборке совпали с рабочей веткой.

Подтверждены настоящими compositor captures: Home 1920×1080, Settings,
изменение размера стрелками, сохранение процента после перезапуска оболочки,
нажатие XTest pointer на + (105→110), удержание видимой выбранной строки,
Reset (100%) и возврат к Home. Это удалённый ввод в живой UI, а не подтверждение
ощущения физических кнопок/тача владельцем. В журнале процесса QML ошибок нет.
База quick_check=ok; число игровых сессий до/после 130, последняя дата запуска
не изменилась. Громкость оставлена 0%. На Odin оставлен Handheld / 100%.
Личные кадры/receipt хранятся только в локальном work/evidence/home18-odin.
