## Подготовленный механизм

- Одна игра, один захват и один аппаратный H.264-кодировщик хозяина. Opus также
  кодируется один раз. Гости получают отдельные пакеты, ключи, P2/P3/P4 и прямые
  ICE-соединения. Сервер владельца и Fluxer не переносят игровой медиапоток.
- Организатор использует существующие места, Ready, подготовку текущей игры,
  Home/выход, поздний вход и защиту сохранений. Отзыв одного допуска освобождает
  только его порт/соединение. Игра хозяина сохраняется.
- Локальные адреса helper изолированы для каждой пары; несколько соединений на
  устройстве не конкурируют за один фиксированный loopback endpoint.
- Рецепт резервирует точные имена P2/P3/P4. Кандидат ограничивает число игроков
  профилем: до четырёх для FCEUmm/Snes9x, до двух для Genesis Plus GX. Для SNES
  подготовлен Multitap на втором порту. Это исходники рецепта, не аппаратная
  или игровая приёмка четырёх контроллеров.
- Первый IDR не расходуется до появления получателя. Для позднего входа нужен
  фактический IDR с SPS/PPS, обычного I-кадра недостаточно. Используется штатный
  [запрос ключевого кадра GStreamer](https://gstreamer.freedesktop.org/documentation/additional/design/keyframe-force.html).
- Исправлена очередь Fluxer: новый снимок лобби больше не подменяет старый
  перед уже ожидающей командой тому же участнику. Иначе новый serial делал
  команду устаревшей на приёмнике. Регрессия проверяет state → runtime-signal →
  state; соседние последние снимки всё ещё объединяются.

## Проверки и ограничения

| Проверка | Результат и граница |
| --- | --- |
| ARM CTest общих служб | 8/8: lobby, social, runtime_multiplayer, history, diagnostics, input lease, group grants, overlay. Включены две настоящие параллельные ICE-пары и независимый отзыв P2/P3/P4 |

| Медиакомпоненты | 4/4 CTest; обычный I-кадр и IDR без параметров не принимаются за начальный кадр |
| Один общий host + два клиента Flip → Odin | Два подключения и P2/P3 созданы. Изображение **не прошло проверку**: первый клиент получил звук, но 0 декодированных кадров. Это не успешная игра втроём |
| Исправленное начало потока, локальный стенд Flip | Одна NES Pong, один кодировщик, один headless-клиент: 285/285 принятых/декодированных кадров, 2006 Opus/PCM блоков. Не парная/WAN-приёмка и не физическая проверка управления |
| Новый парный цикл через Fluxer | Запуск/выход достигнуты, но чёрный экран и прерывание теста не позволяют принять цикл. Старые результаты предыдущей сборки сохранены отдельно |

Две ICE-пары и три разрешения не означают трёх физических пользователей.
Третьего устройства/живого третьего аккаунта в этом проходе нет. Локальный
титульный экран имел нулевую амплитуду; счётчики PCM не являются новой проверкой
слышимости или игрового звука.

## Системная зависимость и восстановление

На штатном Iris Flip первый буфер содержит NAL 9/7/8/5. Последующие помеченные
ключевыми буферы содержат 9/1: обычные I-кадры без нового IDR/SPS/PPS.
Поздний получатель не может начать декодирование. Это соответствует уже
воспроизведённому [дефекту Iris](ARMADA_IRIS_ENCODER.md); готовый upstream-патч
запроса IDR хранится в `packaging/kernel/iris`. Дополнительные копии игры,
дополнительные кодировщики и обходной протокол не добавлены.

**Системная поставка исправления Iris теперь является непосредственной
зависимостью общего многогостевого потока на Flip**, а не только последующей
проверкой картинки. Начальный кадр этого не заменяет. Горячую выгрузку драйвера
Odin не повторять: нужен восстанавливаемый системный вариант.

Во время кандидатных проверок оба сеанса Gamescope завершились с ABRT; сеансы
перезапущены, ядро и установленные бинарники не заменялись. Ранее пройденная
проверка capture lifecycle не доказывает исправность нового сценария. Причина
этого завершения пока не установлена. Позже Odin стал нестабильно отвечать на
SSH: команды и SFTP зависают. Владелец уведомлён о необходимости перезагрузки.
Новая аппаратная приёмка ждёт восстановления. После локального стенда на Flip
подтверждены прежний SHA установленной оболочки, активный session service,
отсутствие проверочных процессов/игр/remote pads/каталогов соединений и громкость
0%. Текущее состояние оболочки Odin из-за зависания SSH подтвердить не удалось.

## Точная очередь продолжения

1. После перезагрузки Odin проверить новую загрузку, обычный TrainerOS, отсутствие
   проверочных процессов и громкость 0%. Кандидат хранится отдельно; сверить его
   manifest перед использованием. Не восстанавливать старую тестовую комнату.
2. Завершить восстанавливаемую системную поставку уже подготовленного исправления
   Iris. На Flip подтвердить новый IDR/SPS после запроса, не только принятие
   события. Odin не подвергать горячей выгрузке.
3. Один host → два клиента: первый кадр обоих, поздний P3, уход P2, непрерывные
   изображение/ввод P3, повторный P2, неизменный процесс игры и один кодировщик.
   Затем закрытие всей группы без падения Gamescope.
4. Изменённый цикл лобби через Fluxer с исправленной очередью; независимые реальные
   порты поддерживаемого core. Не повторять несвязанные пройденные платформы.
5. Затем обычная сборка, manifest из девяти файлов, установка на оба устройства
   и обновление статуса. PS3/Switch, собственный TURN и сложные NAT вне шага.
