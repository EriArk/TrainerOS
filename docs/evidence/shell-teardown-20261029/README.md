# Штатный выход TrainerOS и Steam Gaming Mode, 29 октября 2026

Продолжение [исправления перехода в Steam](../steam-session-20261029/README.md).
Граница S15 → S04: фоновые системные службы должны завершаться без обращения
к уже разобранному интерфейсу. Защищённый выход игры остаётся у SessionState /
AdventureLaunchController; деструкторы не заменяют сохранение и финализацию игры.

## Причина и исправление

На установленном Odin обычное закрытие окна через WM_DELETE_WINDOW →
SessionState.requestExit воспроизвело SIGABRT. Живой GDB дал цепочку:

```text
ShellController::~ShellController
PowerControl::~PowerControl
QProcess::waitForFinished → finished
ShellController::syncExperience → homeAdventure
malloc_printerr → abort
```

Сигнал завершения power-service синхронно вызывал обновление ShellController,
чьи QString / коллекции уже были уничтожены. Автоматическое отключение Qt
в базовом QObject-деструкторе наступало слишком поздно.
Повторная проверка после изоляции PowerControl выявила тот же вход через
AppsController::~AppsController → QProcess::finished. Поэтому исправление
включает границу композиции оболочки, а не только первый аварийный обработчик.
Ещё один установленный повтор выявил более ранний SIGSEGV: уничтожение runtime
службы → Lobby reconcile → Home/Shell changed → Main callback с уже уничтоженным
`lastMultiplayerState`. Граница должна закрываться сразу после app.exec, до
начала разрушения объектов, а не только в деструкторе ShellController.

- SessionConnections хранит соединения, созданные слоем Main, и отключает их
  после окончания главного цикла / при выходе из setup. Это касается всех
  источников composition-событий, а не только changed оболочки; внутренние
  соединения сервисов не затрагиваются. Повторный выбор Trainer создаёт новый scope.
- ShellController до разрушения полей отключает собственные исходящие
  соединения и входящие соединения от принадлежащих ему служб, их QObject-потомков
  и Experience-модулей. Очистка модулей выполняется при ещё живых службах хоста.
  Внутренние соединения служб, включая завершение рабочих потоков, сохраняются.
- PowerControl отключает callbacks процесса до EOF / ожидания / kill.
  Соединения создаются один раз в конструкторе; повторный запуск службы не
  накапливает обработчики. Ошибка службы во время работы по-прежнему видна.
- NetworkService применяет ту же границу до terminate / wait, останавливает
  timeout и дожидается kill при необходимости.
- ProcessService отключает callbacks до разрушения полей и QProcess. Обычный
  stop / complete и защищённая финализация игры сохранены.
- AppsController отключает процесс и таймер ожидания перед EOF / wait;
  SocialMedia при уничтожении очищает ресурсы без публичного changed.
- Регрессия ServiceTeardownTests запускает настоящий дочерний процесс:
  проверяет уведомления при жизни службы и их отсутствие при уничтожении
  PowerControl, NetworkService, ProcessService, AppsController и SocialMedia.
  ExperienceTests намеренно посылает события службы и модуля во время
  уничтожения оболочки; callbacks не должны вызываться. ProcessTests проверяет
  обычный запуск, остановку, отмену и финализацию.
  Проверка SessionConnections удаляет захваченное состояние раньше источника
  `destroyed`, сохраняя отдельный внутренний cleanup callback источника.

## Доказательства поставки

- ARM Release собран на Odin, исходники/объекты/контейнеры/временные файлы тестов
  находятся на microSD. Исходники src сверены с текущим main и этой правкой.
- CTest: **4/4** набора прошли; Qt Test сообщает **69 passed, 0 failed**:
  ServiceTeardown 8, Apps 12, Experience 30, Process 19, включая init/cleanup.
  Первая попытка ProcessTests использовала отсутствующий TMPDIR старого builder;
  итоговый запуск использует существующий временный каталог на microSD.
- SHA-256 итогового traineros:
  `b667747b3adcd0833aac1b7ca6e5e25324668f912e53dff38852be760333cabf`.
- Одинаковая итоговая сборка установлена и запущена на Odin и Flip; hash живых
  процессов совпал. Перед заменой сохранены бинарник, настройки и SQLite backup.
  После установки четыре защищённые таблицы, настройки и avatar pack каждой
  портативки совпали с её собственным снимком; SQLite quick_check — ok.
- На Odin тот же WM_DELETE_WINDOW → SessionState.requestExit под GDB теперь
  завершился `exited normally`; supervisor / TrainerOS unit остановились.
  Аварийного сигнала и автоматического возврата после падения в этом повторе нет.

- Из свежего TrainerOS выполнен обычный Start → Switch → Steam Gaming Mode →
  Continue. TrainerOS unit остановлен, Steam Gamescope unit активен. После
  загрузки визуально проверены меню Steam и главный экран с библиотекой;
  выбор соседней игры изменил фокус, название и фон. Это проверка изображения
  и отклика интерфейса, а не только наличия процесса. Steam-вход сохранился.
- Odin оставлен в Steam с громкостью 0%; Flip — в обновлённом TrainerOS.
  Устройства не перезагружались, сон и игры не запускались.

## Незавершённая проверка и соседний функционал

Переход в Steam на Flip, физические кнопки, запуск Steam-игр и обычный обратный
маршрут из меню Steam в TrainerOS этим проходом не подтверждаются. Возврат
на Odin для диагностики выполнялся установленным session helper. Интеграция
Steam library остаётся отдельной незавершённой частью R117. Предыдущие
аварийные дампы — диагностическая история, а не сбой итогового проверенного выхода.
