# Лобби: план полного пользовательского цикла

Актуализирован **13 октября 2026** после повторного чтения текущих issues
#132, #135, #172 и #179–187 и сверки с исходниками; привязка L01/L02 продолжена после `7000522`.
Это рабочий план выполнения, а не отчёт о готовности. Пользователь отдельно
подтвердил: подключать уже работающий мультиплеер и сделать кругляши поверх игры.
Ожидание портативок не блокирует независимую реализацию этих связей.

Привязка `RuntimeLobby.cpp` / `GameParty::bindLobby` включена в сборку: подготовка
проверяет локальный контент, выбранные места и прежнее сохранение; согласованный
Ready передаётся существующей игровой партии без второго приглашения/Start.
Свёрнутое приглашение лобби использует общую пассивную поверхность.
[Поведение, проверки и границы](LOBBY.md#связка-лобби-и-игровых-служб--13-октября-2026).
13 октября L01–L04 установлены на Flip/Odin после обновления Armada. Восстановление
комнаты/разговора и явные результаты исключения/закрытия проверены через живой
Fluxer; [точные доказательства и оставшаяся приёмка](LOBBY_RECOVERY.md).
L01/L02 не закрыты без полного игрового цикла; физический ввод/capture L03 и новая
временная дружба L04 остаются открытыми. Текущая поставка L05 описана в [LOBBY_MEDIA](LOBBY_MEDIA.md); далее L06, L07 и L08.
Следовать уточнению владельца: исправлять общую причину и контракт службы,
не наращивать отдельные обходы для экранов или игр.

## Карта входов и переходов

Все входы ведут к одной идентичности лобби. GameParty остаётся внутренней
партией выбранной игры. Знакомство, разговор и членство не заканчиваются вместе
с процессом эмулятора. Вступление в лобби не означает Ready или согласие закрыть игру.

| Вход | Уже известный контекст | Обязательный путь | Текущий разрыв |
| --- | --- | --- | --- |
| Home, выбранная игра | Точная локальная игра и Trainer | Играть вместе → режим, если их несколько → создать/открыть лобби с этой игрой → люди или публикация | Online Together ведёт в лобби; Nearby сохранён отдельным существующим маршрутом |
| Collections / карточка библиотеки | Выбранная карточка | Тот же путь; обычная A продолжает запускать одиночную игру | Есть общая привязка; проверка запуска из карточки на устройствах впереди |
| DM / профиль человека | Конкретный собеседник | Лобби без игры → приглашение этому человеку → совместный выбор игры | People-first объединён; провайдерная доставка проверяется отдельно |
| Групповой чат | Разговор и его участники | Создать/открыть лобби в контексте группы, пригласить участников с явным согласием каждого | Play with group и новые предложения Join ведут в лобби; каждый принимает сам |
| Комьюнити / канал / карточка участника | Комьюнити, канал либо выбранный человек | Каталог/создание лобби либо приглашение выбранному человеку | Добавлены создание/каталог и приглашение из профиля; всё комьюнити не приглашается |
| Публичный каталог | ID лобби, организатор и правила доступа | Запрос/вступление → та же комната → подготовка выбранной игры | Общий runtime подключён; реальная цепочка каталог → портативки ещё не проверена |
| Работающая игра, Home / Game Options | Неизменяемый ID реальной сессии и игры | Открыть то же лобби с этой игрой, сохранив процесс до явного согласия на перезапуск | Online ведёт в лобби; процесс сохраняется до явного подтверждения выхода |
| Свёрнутая игра | Та же живая сессия | Лобби / вернуться в игру; выбранная в библиотеке другая игра не подменяет живую | Проверить все действия общего меню и возврат фокуса |
| Входящее приглашение во время игры | Приглашение, отправитель, срок | Развернуть → принять / позже / отклонить; позже → кругляш; самостоятельное закрытие игры не убирает приглашение | Лобби подключено к значку; выход из игры не удаляет приглашение, закрытие комнаты отзывает его |
| Активность друга / партия группы / повторное подключение | Конкретная комната и текущая игра | Join/Ask → лобби → безопасный live join, если доказан, иначе новый общий запуск по Ready | Новые объявления несут ID лобби; прежние партии сохранены для совместимости. Live join остаётся L06 |
| Круглый аватар игрока | Конкретный участник текущей игры | Мини-чат → общая клавиатура → отправить → вернуть управление игре | Общий мини-DM реализован; устройство/capture и реальная речь ещё не приняты |
| Зритель трансляции | Комната и выбранный поток | Смотреть без ROM/места → «Хочу играть» → решение хозяина → тот же путь игрока | Просмотр и запрос хозяину реализованы в L05; живое подключение контроллера — L06 |

## Очередь выполнения и критерии окончания

### L01 — единые входы, приглашения и возврат

Источники: [#172](https://github.com/EriArk/TrainerOS/issues/172),
[#132](https://github.com/EriArk/TrainerOS/issues/132),
[#179](https://github.com/EriArk/TrainerOS/issues/179).

- Свести всю таблицу входов к общему контексту: Trainer, выбранная или живая игра,
  человек/разговор/комьюнити, ID лобби, поколение и ID приглашения.
- People-first создаёт комнату без игры; game-first сохраняет точную игру.
  Не спрашивать повторно уже выбранного человека. Выбор нужен только между
  действительно разными игровыми режимами; транспорт выбирается автоматически.
- Приглашение сворачивается, сохраняется после выхода из игры, исчезает при
  отказе/отмене/истечении. Принятие комнаты отдельно от безопасного закрытия игры.
- Сохранить обычный Nearby; показывать только обнаруженные устройства. Связь
  discovery-ID и аккаунта не угадывать по имени. Старые доставленные маршруты
  сохранять работоспособными на время миграции, не объявлять их новым циклом.

**Готово, когда:** для каждого входа есть прямое действие, корректный Back,
проверки смены аккаунта/игры/приглашения и возврат в исходный контекст. Переход
между двумя новыми клиентами не требует параллельного старого мастера приглашения.

### L02 — существующий мультиплеер внутри лобби

Источники: [#132](https://github.com/EriArk/TrainerOS/issues/132),
[#187](https://github.com/EriArk/TrainerOS/issues/187),
[рабочая матрица](MULTIPLAYER_WORKING_MATRIX.md).

- Подключить GameParty и готовые runtime-службы к Prepare → P1–Pn → Ready каждого
  игрока → автоматическому запуску. Второго Start и повторного приглашения нет.
- Подготовка проверяет конкретную игру локально. Чужие библиотеки не сканируются.
  Отсутствующая ROM не выдаётся за готовность; гостевой контент зависит от
  существующих #136–141, согласия и защиты временных файлов.
- Не выдумывать новые сетевые механизмы. Первая волна: NES/SNES/Mega Drive/PS1,
  GameCube/Wii и другие уже готовые маршруты. Использовать общую интеграцию,
  а не повторять один проект для каждого RetroArch core.
- PS2 остаётся обязательным: ARMSX2 native LAN/server online с реальными
  предпосылками. LRPS2 не возобновлять. Couch — одна консоль и отдельные геймпады;
  pass-P1 не подставлять вместо этого. Remote Play — L07.
- Solo Ready не запрещается искусственным минимумом. Если конкретный режим
  требует несколько эмулируемых машин, объяснить его настоящее ограничение.
  Места должны совпадать с реальными портами; текущие ограничения host/P1 и
  четырёх мест проверить и отразить, не выдавать произвольные P1–P16 за поддержку.
- Подготовка, ошибка, отмена и завершение возвращают в ту же комнату. Смена игры
  сбрасывает только игровые места/Ready, сохраняя людей, разговор и звонок.

**Готово, когда:** две стороны проходят весь цикл дважды с другой игрой без
повторного приглашения; запуск происходит ровно один раз после всех Ready;
отказ сохранения/старый ответ/обрыв не запускает другую игру. Ранее доказанный
gameplay переиспользуется, а новая связка с лобби проверяется отдельно.

### L03 — кругляши игроков и мини-чат поверх игры

Источник: [#183](https://github.com/EriArk/TrainerOS/issues/183).

**13 октября:** аватары, unread, перемещение, мини-DM и общий input lease
реализованы и установлены на обе портативки. [Проверки и ограничения](PLAYER_OVERLAY.md).
Физический ввод и чистый Gamescope capture остаются открытыми;
реальная речь и исключение HUD из будущего стрима проверяются с L05/L07.

- Небольшие круглые Fluxer-аватары именно игроков P1–Pn, с инициалами при отсутствии
  картинки. Перетаскивание touch/mouse и доступная через Home настройка геймпадом.
  Позиция сохраняется для Trainer и ограничивается краями/TV safe area.
- Число непрочитанных на соответствующем аватаре берётся из Fluxer; посторонние
  контакты остаются в обычных уведомлениях. Не заводить второй счётчик.
- Нажатие открывает маленький пузырь DM с существующими правами, историей,
  черновиком и клавиатурой. Отправка/Back возвращает управление тому же процессу.
- Пассивные кругляши не забирают кнопки; ввод перехватывается только намеренно
  и только в своей области. Использовать существующие overlay/input lease и watchdog.
- Кольцо речи включать только по проверенному событию конкретного участника.
  Для этого нужна связь account ID ↔ участник медиасессии ↔ реальная речь из L05.
  Подключённый микрофон, общий voice count и mute не заменяют такое событие.
- Личный HUD/DM не попадает в игровой capture или трансляцию. На 2–4 игроках
  кругляши не становятся большой боковой панелью; больший состав сворачивается.

**Готово, когда:** проверены адресат DM, unread, перемещение/resize/restart,
клавиатура, возврат управления и исключение HUD из capture. Речь имеет отдельное
реальное подтверждение. До него весь #183 не считается завершённым.

### L04 — восстановление комнаты и полный жизненный цикл

- Временные друзья и «Недавно вместе» привязаны к реальному членству. Сохранение
  дружбы, существующие контакты, блокировки и неопределённые ответы защищены.
- Потеря каталога не завершает игру. Потеря организатора, исключение, закрытие,
  reconnect и перезапуск имеют явные результаты, а не зависшую «готовность».
- Восстановление членства реализовано и проверено при перезапуске гостя/хозяина
  через живой Fluxer. Старый билет запуска и Ready сбрасываются; исключение и
  закрытие не отменяются перезапуском. [Доказательства L04](LOBBY_RECOVERY.md).
- Различать выход из игры, выход из лобби, выход из разговора и отключение звонка.
  Безопасный выход проходит существующие capture/сохранение/settlement.

**Готово, когда:** есть проверки отказов на стыках L01–L03, живая проверка
временной дружбы и восстановления; общение переживает смену игр и обычный выход.

### L05 — трансляции, зрители и общий голос

**Уточнение владельца, 13 октября:** использовать готовые голос, индикацию речи
и Go Live Fluxer. Перед новой социальной/медиафункцией сверяться со
[справочником возможностей](FLUXER_CAPABILITIES_RU.md). Текущая интеграция уже
использует LiveKit; собственный медиатранспорт не нужен. Будущая замена стека
Fluxer записана отдельно от действующего контракта. Наша работа — привязки
участников, UI и проверенный захват игры без личной оболочки.

**Реализация 13 октября:** публикация игрового окна и его звука, выбор потока,
роль зрителя, запрос хозяину и кольца речи используют существующий Fluxer/LiveKit.
Остановка просмотра/игры сохраняет общий звонок. [Доставка, проверки и ограничения](LOBBY_MEDIA.md)
отделены от полной приёмки. Go Live не передаёт управление; это остаётся L07.

Источники: [#181](https://github.com/EriArk/TrainerOS/issues/181),
[#182](https://github.com/EriArk/TrainerOS/issues/182),
[#180](https://github.com/EriArk/TrainerOS/issues/180).

- Переиспользовать подходящую готовую передачу видео/звука; сначала проверить
  реальный ARM encode/decode/capture, затем интегрировать в лобби.
- Смотреть можно без ROM, геймпада и Ready. Игрок, зритель и стример различаются;
  несколько согласованных потоков выбираются независимо.
- Полная комната остаётся в каталоге при живой трансляции. Публичный голос —
  явная смена аудитории, один общий разговор; self-mute выключает человека для всех.
- «Хочу играть» даёт хозяину принять/позже/отклонить, сохраняя текущую игру.
  Остановка потока освобождает capture; личные сообщения и оболочка не транслируются.

**Готово, когда:** зритель без ROM смотрит solo/полную комнату, слышит разрешённый
общий разговор без удвоения, не получает управление; остановка и потеря связи
освобождают ресурсы. Настоящий звук/гарнитуры проверяются отдельно на устройствах.

### L06 — вход в уже работающую игру, где он действительно поддержан

Источник: [#184](https://github.com/EriArk/TrainerOS/issues/184).

- Разрешение хозяина и реальная capability выбранного runtime; начать с
  FCEUmm/Snes9x/Genesis Plus GX. Сохранить PID хозяина, прогресс и capture.
- Отличать первое присоединение к solo от ранее проверенного rejoin.
  TrainerOS не определяет раунды/уровни; когда использовать P2, решает игра.
- Где live join отсутствует, предлагать новый общий запуск по Ready в том же
  лобби. Не закрывать работающую игру молча.

**Готово, когда:** подтверждён первый live P2 без перезапуска хотя бы на одном
точном runtime; неподдерживаемые режимы не показывают эту возможность.

### L07 — универсальный Remote Play

Источник: [#186](https://github.com/EriArk/TrainerOS/issues/186).

Одна копия игры у хозяина, видео/звук гостю, отдельные разрешённые геймпады P1–Pn.
Переиспользовать передачу из L05, но просмотр не выдаёт право ввода. При обрыве
отпускать кнопки; гость не управляет Home/Exit/файлами хозяина. Сохранения принадлежат
хозяину. Native NetPlay/Link остаётся предпочтительным, когда уже поддержан.

**Готово, когда:** две физические портативки в разных внешних сетях дают пригодные
видео/звук и независимый ввод, с отзывом доступа и безопасным выходом.

### L08 — сквозная приёмка и публикация результата

Источник: [#135](https://github.com/EriArk/TrainerOS/issues/135).

Проверить карту входов целиком: game-first, people-first, группа, комьюнити,
не-друг из каталога, игра/свёрнутая игра, приглашение/позже, повторная игра,
ошибка/reconnect, звонок, HUD, зритель и Remote Play. Физические кнопки/touch,
гарнитуры, TV-композиция и разные ISP — отдельные условия, не QML-имитация.
Проверенные пункты закрывать доказательствами, а не количеством тестов.

## Шпаргалка перед каждой следующей правкой

1. Прочитать активный пункт CURRENT_TASKS и соответствующие строки этого плана.
2. Сформулировать видимый пользователю результат целого шага и его точки входа.
3. Найти существующий сервис; сохранить чужой WIP и прежние доказательства.
4. Реализовать действие, UI, обратный переход, ошибки и очистку одним связным шагом.
5. Проверить затронутые стыки. Не повторять прошедшие игровые тесты без причины.
