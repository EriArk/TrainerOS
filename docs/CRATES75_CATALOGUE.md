Каталог подключается через отдельный валидируемый документ. Владелец поручил
самостоятельно подобрать небольшую временную open-source подборку: 2048, Hextris,

настоящие upstream-изображения не выдаются за запуск на TrainerOS. Crates-пакеты
ещё не опубликованы: списки релизов пусты. Источники и SHA-256 оригиналов —
[здесь](../assets/crates/examples/README.md). What's New содержит все пять, тематические
ящики — ручную подборку; Workshop оставлен для собственных проектов. Мини-утилиты
в данном проходе — тестовые примеры по просьбе владельца, не замена обычному Bazaar.
Синтетические проекты/версии существуют только в тестовой сборке.

Сетевой delta-feed #146, установка #148, отзывы #151 и пожертвования #150 остаются
следующими этапами. В этом проходе не рисуем кнопки несуществующих операций,
не выдумываем installed/ratings, не публикуем релизы и не запускаем пакеты.
Метаданные версии не дают разрешения на установку или запуск.

## Реализация и управление

- `CratesCatalogue` отделяет проекты от принадлежности к ящикам; документ
  разбирается атомарно, с ограничениями размера и ссылок. Неизвестная совместимость
  остаётся непроверенной. Команды, статусы установки и рейтинги из него не принимаются.
- На экране создаётся не больше шести карточек. Каталог загружается в QML только
  при открытии ящика и освобождается при уходе с вкладки; контроллер сохраняет
  отдельный выбор по устойчивому ID для каждого ящика. Навигация по снимкам и
  версиям не пересоздаёт карточки каталога. Декодирование изображений ограничено.
- Крестовина/стик перемещает выбор, A открывает детали; края списка не зациклены.
  Стрелки страницы, колесо и действия ScrollUp/Down переключают страницы.
  B последовательно закрывает версии, карточку и ящик. X/Y и L1/R1/L2/R2
  остаются глобальными; вернувшись, пользователь получает прежнюю страницу.
- В карточке влево/вправо переключает снимки, вверх/вниз прокручивает описание.
  Select открывает версии, когда они есть; версии выбираются вверх/вниз, A/B
  возвращает к карточке. Исправлен перехват Select общим диспетчером Shell.
  Все действия имеют прямые touch-цели, описание и примечания прокручиваются.
- Маленькая карточка кадрирует изображение; большой просмотр показывает его
  целиком с сохранением пропорций. Пропавшее изображение получает нейтральный
  знак типа проекта, пустой ящик — оформленное состояние, а не фиктивные товары.

## Проверки

Профильные проверки выполняются на ARM: `crates_showcase` и `crates_qml_smoke`.
Во втором сценарии используется настоящий Shell/QML и виртуальный SDL-контроллер:
пагинация, B/Select, снимки, версии, глобальная панель, смена вкладок, 960×540 и
1280×800, длинный текст, пустой ящик, отсутствующая картинка, затем настоящий
встроенный каталог. Синтетические проекты не компилируются в production.
Физическая оценка владельцем, отдельные масштабы/TV, установка проектов и их
контроллерная совместимость остаются самостоятельной приёмкой.

Локальные логи и снимки: `work/crates75/`, реальные captures —
`work/evidence/ra56-{odin,flip}/crates75-*.png`. Они не включаются в публичный commit,
README-скриншоты не заменяются.
