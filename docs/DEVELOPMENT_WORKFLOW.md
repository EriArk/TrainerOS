# Рабочий цикл

1. Подтвердить checkout/ветку/upstream, понять и сохранить WIP. Прочитать
   [текущую задачу](CURRENT_TASKS.md), профильный документ и живые связанные issues.
   Последнее решение владельца важнее старого плана; значимую развилку уточнить.
2. Назвать результат и уровень рассуждений. При смене рекомендации остановиться
   до явного продолжения; не утверждать, что настройка владельца изменена.
3. Реализовать целую согласованную цепочку, используя общие сервисы. Тест/скриншот
   сам по себе не заменяет обещанный результат. Не добавлять спекулятивную работу.
4. Проверить соответствующие риски, обновить актуальную документацию и публикации.
5. Явно stage проверенные пути, inspect staged diff, commit, fetch, push в
   подтверждённую ветку, сверить remote SHA. Это обычный разрешённый цикл.

## Проверки

Сборка: [DEVELOPMENT](DEVELOPMENT.md). Выбирать проверки по изменению: реальные
дочерние процессы для lifecycle, reopen/migration для persistence, SDL/controller
и фактический рендер для UI. Проверять Back/фокус/скролл, touch, offline/empty/error,
портативный landscape и читаемость. Test fixtures не доказывают аппаратную приёмку.
Если изменились testing guards/packaging/composition, проверить production build.
Пройденное повторять только при изменении затронутого кода, сбое или названном риске.
Docs-only проход: содержание, ссылки, `git diff --check`; без лишних device/build тестов.

`link_peer` использует порт 47845. Когда TrainerOS работает на build host, выполнять
протокольные тесты в отдельном network namespace (`--network=none`, loopback и
нужные зависимости/mounts). Не запускать тест против live listener в host network,
не останавливать пользовательскую сессию ради коллизии и не ослаблять assertions.

## Устройства

Доставка включает оба доступных Flip/Odin и support files. Сначала проверить SSH,
текущую сессию/активную игру; не менять устройство во время игры/save transaction.
Сохранить его собственные профили, ROMs, saves, настройки и boot preference.
Проверить live-версию на каждом отдельно. Недоступное устройство явно остаётся
необновлённым. Предпочесть bounded process/session recovery; если нужен reboot,
сразу сообщить. Odin после удалённых проверок оставлять с громкостью 0%.

Сборка на Linux-сервере не доказывает ARM64/устройство. Синтетический ввод/звук не
закрывает физические кнопки, прослушивание и headset. LAN/forced relay не закрывает
different-network acceptance. Оставшиеся внешние условия перечислить один раз,
не производить повторные «проверочные этапы» без изменений.

## Документы и Git

AGENTS — постоянные правила; PRODUCT_SPEC — контракт; CURRENT_TASKS — текущие
галочки/приёмка; ROADMAP — короткая очередь; issues — backlog; commits/CHANGELOG —
история. Не создавать отдельный файл на каждое передвижение кнопки. Технический
документ нужен для механизма, ограничений, восстановления или неповторимого знания.

PROJECT_STATUS и CHANGELOG обновляются по-русски в том же meaningful commit.
Различать исходники/тесты/установку/наблюдаемое поведение/план; ссылки на датированную
проверку не являются новой проверкой. Исторический CHANGELOG не переписывать под
новый UX. Прежние ссылки можно закрепить на коммит с явной исторической ролью.

Stage явные пути. Проверить `git diff --cached`, `git diff --cached --check` и
инвентарь. Не включать builds/private reports/secrets/game data. Учитывать
`.gitattributes`, не менять глобальный autocrlf ради предупреждения. Fetch перед
push; сравнить HEAD с **реальным upstream**, не предполагать main. Разрешить divergence
без потери чужой работы, не force-push. Сверить удалённый hash и итоговый status.
GitHub Actions отключён; не восстанавливать workflow и не ждать CI.

Adapter edits требуют актуального [knowledge register](adapters/README.md),
export/reusable copies и `tools/check-adapter-knowledge.py`. Данные игр/секреты
остаются вне Git. Финальный ответ: результат, проверки, commit, ограничения и дальше.
