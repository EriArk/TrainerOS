## Владелец и путь игрока

S11 Backend владеет привязкой, подтверждениями и прежним журналом Искр.
S01 удостоверяет игрока через Fluxer. S04 открывает браузер из
Профиль → Поддержка и возвращается в тот же профиль; SDK и игры не получают
Patreon credentials, произвольный URL или возможность задавать множитель.

`GET /v1/me/support` сообщает готовность провайдера, состояние привязки,
время проверки и действующий множитель. Авторизованный
`POST /v1/me/support/patreon/attempts` принимает S256 claim challenge и
ограниченный loopback return URI. Начало браузерной авторизации одноразовое;
callback проверяет state и Secure/HttpOnly/SameSite cookie. Временные токены
шифруются Fernet серверным ключом. Ссылка возврата содержит только attempt и
одноразовое доказательство передачи, не токен Patreon.

`POST /v1/me/support/patreon/claim` требует исходную сессию TrainerOS,
claim verifier и handoff. После свежего чтения Patreon API v2 сервер проверяет
владельца и связывает Patreon subject с одним игроком. Новый вход, отключение,
отзыв сессии и смена владельца отсекают поздние ответы. Другой Patreon subject
не заменяет уже привязанный: перенос между аккаунтами остаётся отдельной
операцией восстановления, которой сейчас нет.

`POST /v1/me/support/patreon/check` повторяет проверку.
`DELETE /v1/me/support/patreon` удаляет credentials и прекращает множитель,
сохраняя владение привязкой, баланс, журнал и покупки. Оболочка просит подтвердить
отключение и объясняет: **это не отменяет платежи в Patreon**.

## Подтверждение и начисления

Только собственная campaign и конкретные tier IDs определяют ×2/×3.
Сумма платежа сама по себе не выбирает уровень. Для первой реализации нужны
active patron, успешное списание, положительная оплаченная сумма, прошедшая дата
списания и обычное членство без trial/gift. Неоднозначные сведения не дают бонус.
Подарочные и пробные подписки требуют отдельного согласования политики.

Снимок действует максимум 30 минут и не дольше следующей даты списания;
worker перепроверяет его каждые 10 минут. Недоступность Patreon не продлевает
доказательство. Истёкший refresh token не переиспользуется после неоднозначного
сбоя: требуется повторная привязка. Отмена в Patreon отражается по его текущему
праву; paid-period cancellation не определяется по времени прихода события.

Webhook проверяет HMAC-MD5 подпись и лишь назначает свежую проверку.
Событие не содержит команды начисления и не становится «более новым» только
из-за поздней доставки. Lease ограждает параллельные/просроченные чтения;
HTTP выполняется вне SQL-транзакций. Подтверждение и доплата проходят через
`membership.record_verified` и прежнюю блокировку progression account.
Ledger, баланс, audit и outbox фиксируются вместе. Повторный вход, проверка,
понижение/отмена и переход ×2 → ×3 не повторяют уже выданную доплату.

## Развёртывание и границы

Миграция **0013** добавляет зашифрованные привязки и одноразовые попытки.
`TRAINEROS_BACKEND_PATREON_CONFIG_FILE` содержит client ID/secret,
публичный HTTPS origin, campaign, соответствие tiers, Fernet key и webhook secret.
Все секреты остаются вне Git. `deploy/compose.support.yaml` добавляется к
основному compose и OAuth overlay; worker получает разрешённый исходящий доступ.
Резервная копия БД сделана перед миграцией. Старый runtime со схемой 0012 не
является готовым откатом: сохранять журналы и применять совместимый runtime.

Рабочий Backend обновлён; 141 тест на изолированном PostgreSQL прошёл.
Настоящий Patreon прислал тестовый webhook (HTTP 200). После неисправного Resume
в developer portal webhook зарегистрирован официальным API от имени TrainerOS:
его шесть member/pledge triggers включены, `paused=false`, число ошибок 0.
Подпись окончательного webhook дополнительно проверена на рабочем Backend.
Старый portal webhook удалён; дублирующей доставки нет.

Оплаченная подписка, её реальная отмена/продление, живая доплата владельцу и
перенос привязки пока не приняты. Личный Patreon не связывается автоматически с
тестовыми Ren/Mika. [Поставка оболочки и её проверки](../../docs/PLAYER_PROFILE.md)
фиксируются отдельно.

Контракт провайдера: [Patreon API v2](https://docs.patreon.com/).
