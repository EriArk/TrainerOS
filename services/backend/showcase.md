# Публичный игровой профиль

S11/Accounts собирает разрешённую проекцию профиля; S04 показывает её, S13
сохраняет существующие действия общения и лобби. Это дополнение к базовой
`public_profiles` для таблиц результатов, а не новый список друзей.

## Действующие маршруты реализации

Все запросы требуют обычную сессию TrainerOS. Они не принимают игровые токены
и не экспортируют OAuth credentials.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/v1/profiles/{player_uuid}` | Профиль стабильного игрока, в том числе из результатов |
| GET | `/v1/profiles/fluxer/{subject}` | Та же проекция по подтверждённой OAuth-связи |
| GET / PUT | `/v1/me/profile/sharing` | Собственные настройки видимости с проверкой revision |
| PUT | `/v1/me/profile/favorites` | Явно опубликованные названия до пяти любимых игр |

Параметр `before` листает коллекцию целыми играми по последнему факту,
24 игры на страницу. Обычное прохождение, полный набор и Hardcore остаются
одной карточкой. Недоступный/непривязанный профиль возвращает 404;
одинаковые имена не используются для разрешения личности.

Имя и нормализованный рецепт аватара остаются публичной идентичностью.
Уровень и выбранная полка по умолчанию видны подписанным игрокам; история,
активность в профиле и любимые игры по умолчанию скрыты. Доступ — «видно игрокам»
или «только мне», без ложного режима «друзья», основанного лишь на UUID.
Проверка видимости выполняется при каждом запросе, включая следующую страницу.
Просмотр себя со стороны использует тот же маршрут без обхода приватности.

Ответ никогда не включает баланс, XP-операции, цены, квитанции, слоты,
настройки устройства, пути файлов или credentials. Недавние достижения —
только три названия/игры/даты из подтверждённых RA-фактов. История не показывает
приватные строки ledger и не превращает самодекларацию любимой игры в награду.

Публикация любимых игр показывает перед действием до пяти названий из
существующего локального избранного, в алфавитном порядке. Синхронизация
не автоматическая: последующие изменения избранного публикуются новым явным
действием. Настройка активности относится к окну профиля и не меняет
самостоятельные настройки присутствия Fluxer.

`VisitorProfile` не сохраняет чужую проекцию на диск, сбрасывает её при смене
аккаунта/цели и отбрасывает старые ответы. Чужой персонаж строится из доверенного
локального пакета с проверкой revision; неизвестный рецепт не заменяется
образом владельца. Просмотр не меняет собственную одежду и не даёт права на
чужие вещи. Прямой вход по UUID доступен в Shell; отдельного экрана таблиц
результатов в оболочке сейчас нет, игры используют свой существующий Boards API.

Проверки реализации: `tests/test_showcase.py`, `BackendAccountTests`,
`OnlineSmokeScenario`. Доставка и реальные проверки записываются отдельно
в [журнал продолжения](../../docs/evidence/friendprofile-20261028/README.md).
