# Каталог лобби Fluxer

24 октября 2026: в отдельной ветке подготовлено [расширение AbyssME v2](ABYSSME_V2.md).
Старый v1 сохранён, комнаты разделены по версии/приложению, квота остаётся общей:
одна публичная комната на аккаунт. 15 локальных тестов прошли. На сервер это
расширение пока не установлено; сведения о живом сервисе ниже исторические.

Бот отображает публичные лобби в тематических каналах одного комьюнити.
Запись привязана к комнате и организатору; один организатор может опубликовать
несколько встреч (до 32 действующих объявлений). Внутренний `listing` — UUID
объявления, `lobby` в выдаче — UUID комнаты для входа. При смене владельца Fluxer
новый организатор публикует свою запись, не получая права редактировать чужую.
Старая запись отзывается; при потере связи истекает через 180 секунд. Клиент
выбирает более свежую запись по времени бота при различающихся владельцах.
Входной `room` необязателен для совместимости со старым клиентом.
Бот не запускает эмуляторы,
не выдаёт игровые места, не передаёт видео и не распоряжается сохранениями.
Общий контракт: [LOBBY.md](../../docs/LOBBY.md).

17 октября: добавлены каналы `party-games` и `competitive` с прежними правами
каталога. Категорию задаёт создатель лобби, даже до выбора игры; бот не выводит её
из жанра. Перенос меняет канал существующего UUID с удалением старой проекции.
Автоматическое вступление после входа реализует клиент. Установщик бота для
собственных комьюнити/каталогов запланирован на значительно более поздний этап.

## Развёртывание

Python 3.12, изолированное venv, зависимость из `requirements.txt`.
Код размещается в `~/.local/share/traineros-lobby/`, unit — в
`~/.config/systemd/user/`. Запуск: `systemctl --user enable --now
traineros-lobby-directory.service`. Для работы после выхода владельца нужен
включённый user linger. Существующий серверный Python и другие службы не заменяются.
При отсутствии ensurepip можно создать venv через `--without-pip` и использовать
официальный `https://bootstrap.pypa.io/pip/pip.pyz` внутри этого venv.

Закрытый каталог `~/.config/traineros-lobby/` имеет права `0700`, файлы `0600`:

- `credentials.json`: `api_base`, `guild_id`, `application_id`, `bot_token`;
  первоначальный `client_secret` хранится здесь же, рабочему процессу не нужен.
- `directory.json`: `guild_id`, `application_id`, `channels` — соответствие
  тематических ключей ID каналов. Токены никогда не включаются в клиент или Git.

Боту достаточно View Channel / Send Messages / Read Message History.
Администраторские права ему не выдаются. Объявления в категории доступны для
чтения участникам; запись разрешена боту. Создание каналов выполняет владелец.

Остановка: `systemctl --user stop traineros-lobby-directory`. Для отката остановить
службу, вернуть предыдущие файлы кода и запустить её. Сохранять `directory.db` и
закрытые конфигурации: там находятся связи объявлений и запреты восстановления
закрытых записей. Обновление кода не требует сброса токена.

## Протокол и ограничения

LOBBY-57 добавляет необязательные `title` (до 80 символов), `startsAt` (UTC Unix
seconds, 0 — без времени), `members` (0–32) и хэш `avatar`. Имя и аватар берутся
из авторизованного события Fluxer, не из команды. Старые объявления читаются.
Бот не рассылает напоминания: согласие и таймер хранятся на устройстве участника.

Команда приходит в личное сообщение боту от участника комьюнити. Автор берётся
из события Fluxer; поля сообщения не могут подменить владельца. Принимаются только
свежие события (120 секунд), точный префикс `TrainerOS lobby directory`, блок JSON
и версия `v: 1`. Операции `upsert` / `withdraw` / `close`, `lobby` UUID, возрастающий `revision`.

Объявление содержит `status` (choosing/gathering/playing), `access`
(public/approval), `seats`, `available`, `streams` (целое 0–32, по умолчанию 0), `topic` и публичный `game`
(id/title/platform/mode). Для choosing игровой объект отсутствует, места равны нулю.
Приватные лобби не публикуются. `withdraw` скрывает запись и допускает новую
публикацию того же UUID с большей ревизией; `close` оставляет постоянное закрытие. Владелец имеет не более одной действующей записи.
Клиент обновляет запись новой ревизией до истечения 180 секунд; устаревший повтор
не продлевает срок. Публичные поля ограничены явным перечнем, упоминания отключены.
Счётчик мест является объявлением: фактический вход подтверждает организатор.

SQLite сохраняет ревизии, закрытие и отображение UUID в сообщение Fluxer.
После потери ответа на создание бот сначала ищет своё объявление по UUID.
Перенос создаёт запись в новом канале, затем удаляет прежнюю. API-ошибки и 429
оставляют работу для повтора. Недоступность каталога не прекращает игровые сессии.
Клиент должен проверять автора-бота и срок записи, а не доверять тексту любого
пользователя. Служба использует Gateway с heartbeat/resume; после полного
перезапуска очередной heartbeat клиента восстанавливает публикацию.
