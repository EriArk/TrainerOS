# TrainerOS — состояние проекта

**25 октября — SDK, серверные матчи, результаты и общие таблицы.** Установлен
Backend `play-20261025` с миграцией 0005. Общий scorecard preview принимает 2–16
участников; каждый вступает сам, Start фиксирует состав. Поддержаны команды 2/3,
включая 2 против 3, общий счёт стороны, receipts/retries и ограниченные grants,
которые host не передаёт игре. Worker проверяет карточки; согласие всех участников
даёт peer_confirmed, противоречие снимает результат из общих records/wins/statistics.
Есть ничьи 1,1,3, история, уникальные побеждённые, revision pagination/around и
операторский void без удаления исходных решений. S01/S10/S14 используют прежние
account, queue, receipt и outbox, не отдельную систему Lobby.
[Приёмка](docs/evidence/backend-play-20261025/README.md): 57 серверных тестов,
полная Linux-сборка и account/SDK/Settings checks; пять настоящих native hosts →
SDK → HTTP → PostgreSQL/worker, личный матч и 2 против 3, спор/replay/таблицы.
Публичные проверки и изолированный restore прошли; live Lobby сохранён.
В реестре включена только явно названная SDK-демонстрация, production-результаты
не создавались. **Не сделаны:** подключение реальных игр/экранов, точные Golf rules
и проверка физики, trusted-build admission, Elo/статус, турниры, экономика и
оставшаяся эксплуатационная приёмка. Портативки не подключались, GitHub push нет.
Это уточняет прежние «scoped grants/results не реализованы» ниже только в рамках
[нового контракта](sdk/PLAY.md), не объявляет весь Backend завершённым.

**25 октября — вход без ручного кода и привязка оболочки/SDK.** На сервере установлен
`native-return-20261025`: проверенный Fluxer callback возвращает одноразовое
подтверждение на локальный listener, а host получает и хранит сессию отдельно.
Settings получили вход/отмену/выход с общими touch/controller действиями;
безопасное хранилище и refresh изолированы по local Trainer, поздние callbacks
старого владельца не принимаются. Открытие браузера использует существующий
Apps launch guard. SDK `account.identity:1` выдаёт только Player UUID/состояние,
смена аккаунта отзывает старое соединение. Локальный Trainer и Social token независимы.
[Приёмка](docs/evidence/backend-native-return-20261025/README.md): 43 Backend,
12 клиентских checks, 13 SDK passed (1 прежний Godot test skipped), Settings QML
без warnings, полная x86_64-сборка, живой native return/refresh/revoke и restore БД.
На портативки не устанавливалось; целевой vault/foreground/физический ввод,
cleanup при удалении Trainer, scoped grants, push revocation и recovery ещё открыты.
Это заменяет прежнее состояние «native return/SDK не подключены» ниже;
R089 и полный Backend не объявляются завершёнными. GitHub push не выполнялся.

**25 октября — серверный вход через Fluxer включён и проверен.** Секрет отдельного
приложения владельца сохранён на сервере, callback зарегистрирован, OAuth overlay
включён. Живые отмена/consent/повторный вход, выдача сессии, refresh и отзыв прошли;
повторный вход сохранил Player UUID, временные серверные сессии отозваны.
Исправлена политика страницы, из-за которой браузер не передавал Origin формы;
проверки Origin/cookie сохранены. 34 серверных теста и 7 публичных проверок прошли.
[Установленная версия и приёмка](docs/evidence/backend-oauth-live-20261025/README.md).
На этом этапе native return, хранение сессии оболочкой и SDK binding ещё
отсутствовали; они реализованы следующим проходом выше. R089/recovery остаются
открытыми. Портативки не проверялись.

**25 октября — приложение владельца и HTTPS для Backend.** Отдельное OAuth-приложение
**TrainerOS** создано в постоянном аккаунте владельца. Подключён
`https://traineros-api.abysstail.art` через собственный tunnel: `/v1/*` и health/live,
без внешних readiness/OpenAPI и без изменений Lobby/Crates. Семь read-only
проверок публичных маршрутов прошли. На этом этапе секрет/callback/live OAuth
ещё ожидали подтверждения владельца; эта зависимость закрыта следующим проходом выше.
Принят обычный вход с возвратом в TrainerOS без обязательного ручного кода;
native return и shell/SDK binding остаются реализацией, а не готовой функцией.
[Условия и проверка](services/backend/accounts.md),
[свидетельство](docs/evidence/backend-oauth-setup-20261025/README.md).

**25 октября — серверный модуль аккаунтов через Fluxer.** Реализованы постоянный
TrainerOS ID по подтверждённому subject Fluxer, одноразовые попытки входа с PKCE,
подтверждение кодом с устройства, отдельные access/refresh, ротация/отзыв сессий
и событие отзыва в outbox. [Контракт и условия активации](services/backend/accounts.md).
Код и миграции установлены на сервере. Первоначальная поставка была с выключенным
входом; регистрация приложения, HTTPS и живая активация доставлены последующими проходами выше.
Имеющийся Lobby Directory не менялся. Проверки с
изолированной PostgreSQL и контролируемым OAuth-провайдером не означают живой
вход в Fluxer. [Свидетельство](docs/evidence/backend-accounts-20261025/README.md).
R089 остаётся открытым: shell/SDK binding и recovery не приняты; live OAuth принят выше.

**25 октября — общий Backend установлен на сервере.** По новому указанию владельца
сборка и runtime-проверки перенесены на существующий сервер; прежний запрет на
серверную установку в этом чате отменён для Backend. [Серверный каркас](services/backend/README.md)
включает API состояния, PostgreSQL с явной миграцией и ограниченной runtime-ролью,
транзакционные квитанции команд, очередь с lease/fencing и outbox/dedup.
17 интеграционных проверок прошли в отдельном серверном контейнере с настоящей БД.
Установлены отдельные API/worker/PostgreSQL, без публичного ingress и изменения
Lobby-бота. В capabilities пока нет входа, рейтингов, покупок и других продуктовых
функций. SDK/аватар/игры/портативки не менялись. [Приёмка и ограничения](docs/evidence/backend-foundation-20261025/README.md).
Это заменяет прежнее состояние «только проект» для инфраструктуры; R089/R107–R115
остаются открытыми. Временные локальные runtime-файлы перенесены в корзину Windows.

**25 октября — формальные серверные контракты.** [Пакет проекта](services/backend/contracts/README.md)
содержит 67 операций OpenAPI, 122 схемы сообщений, 48 логических сущностей БД,
12 событий и 14 proposed SDK methods для всех 13 модулей архитектуры. Добавлены
разделённая повторная авторизация, ограниченная передача evidence и минимальный
event index для dedup после очистки payload. Существующий avatar recipe сохранён.
Проверки форматов/ссылок/владельцев и 36 граничных примеров прошли локально.
Это проект, не HTTP-сервис и не миграция: runtime, OAuth, PostgreSQL transactions,
серверная установка и портативки не проверялись. R089/R107–R115 остаются открытыми.

**25 октября — вся серверная архитектура перед рабочими сценариями.** По уточнению
владельца подготовлен [общий проект v1](docs/TRAINEROS_BACKEND_PLAN_RU.md#architecture-v1):
модули Accounts/Profiles/Registry/Results/Boards/Competitions/Clans, экономика,
инвентарь и подписки, логическая схема данных, API/SDK, доступы, события,

не предлагается: он остаётся примером будущей приёмки. Продуктовые формулы,
тарифы, сроки хранения и конкретные provider-контракты явно отделены от проекта.
Нового runtime-кода, публичного API и серверной поставки нет; R089/R107–R115
остаются открытыми. Проверены документы/ссылки/diff, не сервер и не портативки.

**25 октября — проект общей серверной системы, подготовка.** Уточнены владельцы
Accounts/Results/Boards/Rewards, общий путь результата через SDK, различия
рекордов и соревновательного рейтинга, проверка гольфа и приёмка первого полного

установка выполняются в основном чате; портативки в этом проходе не затрагивались.

**25 октября — Settings и профили ввода, исходники.** Настройки получили шесть
разделов и лёгкое оформление с тонкими разделителями. Есть выбор семейства
контроллера, семантические Confirm/Back и смена общих подсказок; для PC/native

не установлен. Linux X11/InputPlumber, физические устройства и оформление
владельцем ещё не приняты; все хосты и полный аналог Steam Input не заявляются.
R011/R013/R019 остаются открытыми. Installer/OTA, SDK и multiplayer здесь не расширялись.

**25 октября — Lobby до 16 человек, исходники.** Общий предел комнаты снижен

без автоматического удаления участников. [Контракт](docs/LOBBY.md).
Windows/UCRT64: сборка и CTest `lobby` пройдены; каталог: 27 Python-проверок.
Установка оболочки/бота и живая проверка 16 участников остаются открытыми.

**24 октября — одинаковый сетевой набор на портативках.** Lobby выбирает
стандартный runtime независимо от solo-привязки игры и проверяет сборку/core,

каталоге revision 33. Парный настоящий SDK подтверждает разные образы,

установлены через Crates на обеих консолях; activity-манифесты присутствуют.

[Контракт](sdk/qt/README.md). Оболочка, модели и установщик/OTA не менялись.

объявляют мультиплеер через `traineros-activity.json`: выбор в GameHub Lobby,

## Запуск и мультиплеер

Полный каталог: **107 ID в работе**, включая Xbox original. Владелец добавил PS3/Switch к обычному запуску
18 октября: на Odin проверены небольшие homebrew; ограничения Eden перечислены выше.
Коммерческая совместимость и мультиплеер этих двух систем этим не утверждаются.
LAUNCH-80 исследует готовые лаунчеры общим пакетом и проверяет игры от старых к новым.
Настоящие Cemu/ARMSX2 Libretro на устройствах сохранены; автоматическая миграция
их сейвов не разрешена предположением об «ошибочной привязке».
[Реестр](docs/LAUNCH80_PLATFORM_REGISTER.md), [исследование](docs/LAUNCH80_LAUNCHER_AUDIT.md).

Классические RetroArch, GB/GBC/GBA link, DS, PSP, Dolphin, RMG/N64, Flycast, Azahar и
один Vita homebrew маршрут имеют разные по глубине парные доказательства.
Это не «весь мультиплеер готов»: PS2, Wii U, большие группы/разные сети и
широкая совместимость остаются поимёнными пробелами в
[матрице](docs/EMULATOR_MULTIPLAYER_MATRIX.md) и [записях runtime](docs/emulators/README.md).
Обычный PSP имеет сохранённые проверки; private PSP и полный handoff-каталог остаются незавершёнными.

Remote Play использует P2P отдельного игрового медиапотока; Fluxer spectator stream
его не заменяет. Многогостевой кандидат не принят: Iris/IDR и стабильность Gamescope
остаются зависимостями. [Транспорт](docs/REMOTE_PLAY_TRANSPORT.md),
[кандидат](docs/REMOTE_PLAY_GROUPS.md). Собственный тяжёлый relay не добавляется.

Новый обязательный [стандарт эмуляторов](docs/EMULATOR_STANDARD.md) требует
фиксированных runtime/core/build/protocol/sync settings и проверки peers до старта.
Это усиление цели от [`c6aaac2`](https://github.com/EriArk/TrainerOS/commit/c6aaac2),
не доказательство, что единый admission уже завершён во всех маршрутах.
