# Эмоции и рты персонажа

Общий пакет `trainer-avatar-1` revision 7 содержит лицевые morph targets.
Игра загружает персонажа обычным [способом](AVATAR_QUICKSTART.md), затем управляет
его выражением через `avatar_presenter.gd`. Отдельные модели лиц в игру не нужны.
Нужны вместе revision 6, resolver TrainerOS с поддержкой `eyeBodyMeshes` и
актуальный presenter: вычисление лицевых morphs в Compatibility и применение
vertex-цвета бровей (последнее исправлено вместе с revision 6).

```gdscript
if visual.supports_expression("happy"):
    visual.set_expression("happy", 0.7) # основное выражение, сила 0…1
    visual.react("startled")           # удивление, затем возврат к happy 0.7

visual.set_mouth("smirk", 0.8)         # только рот; брови сохраняются
visual.clear_mouth_override()         # рот снова следует основной эмоции
visual.reset_face()                   # плавный возврат к нейтральному лицу
```

## Что доступно

| Выражение | Назначение |
| --- | --- |
| `neutral` | Спокойное исходное лицо |
| `happy` | Улыбка, немного приподнятые брови |
| `sad` | Грусть, опущенные уголки рта |
| `angry` | Недовольство, нахмуренные брови |
| `surprised` | Удивление, круглый открытый рот |
| `smug` | Ехидная асимметричная улыбка |
| `worried` | Тревога, напряжённый рот |
| `tired` | Усталость, более узкие глаза |
| `laughing` | Смех с открытым ртом |
| `cat_smug` | Самодовольный прищур, разные брови и двойная кошачья улыбка |
| `content` | Довольная улыбка и закрытые глаза-дуги |
| `squeezed` | Сильное зажмуривание `> <` с открытым ртом |
| `love` | Карикатурные сердечки вместо глаз |
| `shocked` | Круглые глаза с маленькими зрачками и открытый рот |

Рты: `rest`, `flat`, `smile`, `frown`, `smirk`, `open`, `laugh`, `tense`, `cat_smile`.
Они общие для всех четырнадцати пар глаз; выбранные глаза, цвета и причёска
сохраняются. Радужка вместе со зрачком/бликами уменьшена до 78% прежнего размера.
В `open`, `laugh`, `tense` видны зубы; в `laugh` также язык.
Все рты, зубы и язык увеличены на 15% относительно первого варианта.
Брови остаются отдельными во всех реакциях, следуют кривизне лба и имеют
дополнительное затемнение выбранного цвета волос для контраста с кожей.
Идентификаторы `round`/`almond` сохранены, но их рисованные участки заменены
модульными глазами с круглыми/миндалевидными пропорциями. Это позволяет всем
14 вариантам закрываться и переходить в карикатурные формы без деформации кожи.

`content`, `laughing`, `squeezed`, `love`, `shocked` временно заменяют глаза
общей геометрией реакции; после `reset_face()` возвращается выбранная пара.
Для законченного карикатурного рисунка используйте силу `1.0`. Изменение силы
и переходы по-прежнему интерполируют геометрию. Обычные эмоции двигают выбранные
веки и брови, а `cat_smug` опускает верхнее веко поверх радужки.

```gdscript
visual.set_expression("cat_smug")
visual.set_expression("love", 1.0, 0.15)
visual.set_mouth("cat_smile") # рот можно использовать отдельно
```

| Реакция | Выражение | Удержание по умолчанию |
| --- | --- | --- |
| `celebrate` | `laughing` | 1,2 с |
| `disappointed` | `sad` | 1,4 с |
| `startled` | `surprised` | 0,7 с |
| `hurt` | `worried` | 0,65 с |

Название реакции обозначает визуальный ответ на игровое событие. Например,
успех задания вызывает `celebrate`, промах — `disappointed`. Игра решает,
когда это уместно; SDK не определяет победителя и не начисляет награды.

## Переходы и приоритет

`set_expression(name, strength=1.0, fade=0.18)` задаёт основное выражение и
отменяет текущую реакцию и ручной рот. `set_mouth(name, strength=1.0, fade=0.12)`
заменяет только рот основной эмоции и отменяет реакцию. `react(name,
strength=1.0, hold=-1.0, fade=0.12)` временно перекрывает лицо целиком, затем
за 0,2 с возвращает основную эмоцию вместе с ручным ртом, если он задан.
Отрицательный `hold` выбирает длительность из пакета. Новая реакция заменяет
предыдущую; очереди и отложенного возврата от старого таймера нет.

Сила ограничена 0…1, переход — 0…2 с, удержание — 0,01…10 с. Нечисловые
`NaN`/бесконечности отклоняются. Неизвестные имена возвращают `false`, сохраняя
текущее лицо. На старом пакете `supports_expression`, `set_expression`,
`set_mouth` и `react` возвращают `false`: обычный персонаж продолжает работать.
Время следует обработке сцены Godot; при остановке обработки переход замерзает.

Выражение относится к конкретному экземпляру персонажа. Оно не сохраняется в
профиле и не входит в appearance recipe. Смена внешности создаёт новый presenter
с нейтральным лицом: при необходимости игра повторно задаёт основную эмоцию.
При отзыве личности вызывайте `clear_identity()` и удаляйте старый visual.
Это очищает таймеры, morph bindings и модель. Телесные `play_action()` работают
независимо; новые лицевые controls не заменяют 46 корректирующих форм тела.

Используйте presenter целиком: в Compatibility он вычисляет лицевые morphs на
CPU из-за обнаруженного искажения отрицательных смещений на handheld GPU.
UV, материалы и скелет сохраняются; тело остаётся на GPU, установившееся лицо
не требует постоянного пересчёта. Mobile использует штатные GPU blend shapes.

## Другие движки и сетевая игра

В полном GLB данные находятся в `extras.trainerFace`: `schema:1`, `controls`,
`mouths`, `expressions` (имя → веса), `reactions` (выражение и удержание),
`speech:false`. Имена targets находятся в `mesh.extras.targetNames`, геометрия —
в стандартных glTF `targets.POSITION` / `targets.NORMAL`. Применяйте значения
к экземплярам мешей по имени, а не к постоянным номерам узлов. Исходные веса
равны нулю. `rest` — все `mouth_*` по нулям; прочие рты задают один target.
Между позами интерполируйте веса, не складывая несколько полных ртов.

Сетевой транспорт эмоций здесь не добавлен. Игра может выводить реакцию из уже
синхронизированного события матча. Если нужен отдельный emote, передавайте его
имя/силу через существующий допущенный игровой канал с проверкой участника,
списка значений и частоты. Не передавайте GLB, пути или идентификатор локального
профиля. Поздно присоединившийся игрок получает текущую эмоцию по правилам игры.

Нейтральный `preview` предназначен для статичных Qt-карточек и не содержит
morph targets. Для выражений загружайте полный `glb`. Готовый Godot-пример
показывает переключатели эмоций, рта, силы и реакций, а также крупный план лица.
Для локального просмотра уже разрешённого дескриптора без оболочки:

```sh
godot --path sdk/godot -- --descriptor=/absolute/path/avatar.json
```

Это явный режим просмотра: используется та же проверка SHA256, ничего не
записывается в профиль. Обычный запуск подключается к действующей TrainerOS.

## Границы этого набора

Слоговые рты, привязка к аудио, lip-sync, моргание и управление направлением
взгляда пока не реализованы. `open` не является универсальной фонемой.
Для будущей речи остаётся отдельный слой управления ртом; текущие имена эмоций
и постоянная внешность не зависят от будущей речевой системы.

Техническая основа: [glTF morph targets](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#morph-targets),
[Godot blend shapes](https://docs.godotengine.org/en/stable/classes/class_meshinstance3d.html#class-meshinstance3d-method-set-blend-shape-value).
Исходники генератора, воспроизведение и проверки:
[исходная основа revision 5](../docs/AVATAR_EXPRESSIONS_20261028.md) и
[обновлённые глаза/реакции revision 6](../docs/AVATAR_CARTOON_20261028.md).
